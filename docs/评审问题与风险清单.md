# 评审问题与风险清单

> **来源**：《浙江农林大学第二十届"东湖杯"大学生课外学术科技作品竞赛作品申报书》
> （作品名：耕云——面向普通农民的除草用药提醒与效果反馈 APP；类别：科技发明制作 B 类）
> **用途**：与策划负责同学逐条对照，形成修订决议。每条均标注严重程度与建议动作。
> **阶段**：本清单只做分析与风险识别，**本阶段不编写任何功能代码**。
> **标记**：【严重】影响资格或核心评分｜【重要】显著影响得分｜【建议】优化项

---

## 一、结论摘要

### 1.1 主线已确认（2026-09-30）

小程序功能主线**以申报书为准**：**除草科普内容 + 农民使用反馈采集**。

早期沟通中提到的"拍照识别病害植物 / 识别农药 + 语音播报"与申报书不一致，**不作为主线**；识别类功能暂不做或后置（该项为教师在研讨会上提出的后续扩展方向，详见 7.2）。

> 影响：申报书全文没有任何"拍照识别"的技术描述（仅"图片上传"用于反馈采集），若开发识别功能，演示内容无法支撑申报书主张的创新点。

### 1.2 三个必须先解决的前提问题

| 编号 | 问题 | 严重程度 |
| --- | --- | --- |
| P1 | 主线方向在团队内存在两种理解（识别工具 vs 除草科普反馈平台），已按上文确认 | 【严重】已处理 |
| P2 | 作品定位偏"创业计划书"，与"大挑"评审维度（科学性/先进性/现实意义）不匹配 | 【严重】 |
| P3 | 申报材料含个人信息，且公开仓库可能影响专利新颖性 | 【严重】 |

## 三、定位与内容结构【严重】

| 编号 | 问题 | 说明与建议 |
| --- | --- | --- |
| S1 | **商业模式篇幅过重** | "五、市场分析"（农药市场 1500—1800 亿元）、"六、经济效益预测"（佣金 3%—5%、报告订阅）属创业赛内容。"大挑"评审不看商业可行性，建议**大幅压缩**，把篇幅让给技术论证与实验数据 |
| S2 | **类别与体量不匹配** | 申报为"科技发明制作 B 类（投入较少的小发明）"，内容却是三阶段、三类用户、含电商交易与专利转化的**平台级工程**。评委易追问"这是小发明还是创业项目"。建议二选一：缩减范围到 B 类应有的体量，或论证其技术必要性 |
| S3 | **三阶段无时间表** | 前期/中期/后期的划分没有起止时间与里程碑，而竞赛要求提交**已完成作品**。建议按竞赛节点倒排，只保留赛期内可完成的阶段 |
| S4 | **作品阶段与展示形式不匹配** | "作品可展示形式"勾选"实物、产品"，但当前只有一份申报书。**答辩现场无实物可演示是致命风险**，需尽早确定可演示的最小闭环 |
| S5 | **范围过大导致不可完成** | 科普 + 社交 + 电商 + 专利对接 + 效果报告，任一项都是完整产品的工作量。建议明确"赛期内做什么、什么明确不做" |

## 四、科学性与先进性论证【重要】

| 编号 | 问题 | 建议动作 |
| --- | --- | --- |
| A1 | **参考文献仅 3 条，其中一条是知乎问答** | "云上智农/天天学农平台功能描述. 知乎农业问答"作为参考文献是硬伤。替换为学术论文、专利、行业标准、官方技术方案等，并补充国内外同类系统的技术对比 |
| A2 | **三处"未见报道"缺乏查新支撑** | 文中多次出现"未见报道""尚未见系统实现"，但 E 表查新报告为空。建议申请科技查新（校图书馆一般可办），或改为有调研依据的表述并附调研过程 |
| A3 | **最直接的竞品被回避** | 文中自己引用"云上智农/全国农业科教云平台 1500 万用户、覆盖 2800 多个县"，却只说"内容互补而非直接竞争"。评委极可能问"为什么农民不用现成的官方平台"。需要一个正面回答（例如：官方平台以单向科普为主，缺少区域化效果数据回流，这正是本作品主张的闭环） |
| A4 | **"技术关键"只有名词没有方法** | "农业知识图谱""效果评估模型""结构化采集与清洗"均无实现层面的说明：知识图谱的本体设计与数据来源？评分模型的指标与权重如何确定？口语化语音反馈如何转成结构化数据？**这是"技术含量"的主战场，目前是空的** |
| A5 | 创新点表述偏模式层面 | 四个创新点中三个是"模式/机制/内容"创新，仅一个是数据创新。建议至少补强一个**可验证的技术创新点** |

## 五、数据、合规与法律责任【严重】（风险等级最高）

| 编号 | 风险 | 说明 | 建议 |
| --- | --- | --- | --- |
| L1 | **推荐具体除草剂品种与剂量** | 文中给出具体品种与"一封一杀"方案。农药使用指导通常由农药经营者或持证农技人员承担，平台系统性给出剂量方案将面临药害责任归属问题 | 剂量类信息必须标注来源；强制免责声明；混配、抗性区域、临近采收期等情形兜底到"咨询当地农技部门" |
| L2 | **农资电商资质** | 农药属限制性经营商品，网络销售需农药经营许可证，平台还须核验入驻方资质 | 这是**硬性合规障碍**，非排期问题。赛期内建议明确不做交易，或改为"信息展示不涉及交易" |
| L3 | **"平台质量背书"是法律承诺** | 原文"平台不直接生产，只做第三方撮合与质量背书" | 删除或改写"背书"表述，避免承担产品责任 |
| L4 | **效果报告卖给企业可能触及农药广告审查** | 若报告被企业用于产品宣传，可能构成农药广告，需审查且禁止功效保证类表述 | 明确报告用途限制（仅内部参考、不作为宣传材料） |
| L5 | **UGC 审核义务被自己写实** | "涉及具体除草剂使用的帖子……自动添加提示"相当于主动承认平台具备识别违规内容的能力，提高了注意义务标准 | 改为"举报入口 + 专家抽检 + 免责声明"，不承诺 100% 覆盖 |
| L6 | **数据合规过于单薄** | "需做脱敏处理和权限管理"一句带过。收集农户位置、种植信息、交易数据涉及《个人信息保护法》 | 明确收集范围、告知同意方式、存储与共享规则；气候数据来源与授权需说明 |
| L7 | **涉农信息准确性** | 建议与用药量若出错可能造成实际损失 | 所有建议标注"以农药标签和当地农技部门指导为准"，数据来源可追溯 |

## 六、指标与可行性【重要】

| 编号 | 申报指标 | 问题 | 建议改为 |
| --- | --- | --- | --- |
| M1 | 注册用户 ≥ 5000 人，日活 ≥ 10% | 竞赛周期内不可能达成，且无佐证 | 邀请 N 位农户完成可用性测试并留存记录 |
| M2 | 社交日均发帖/评论 ≥ 200 条 | 同上，自设陷阱 | 删去或改为"完成 1 个试点村的社群运营记录" |
| M3 | 经验帖专家审核覆盖率 100% | 无专家资源承诺 | 明确专家来源与抽检比例 |
| M4 | 合作企业 ≥ 3 家、可转化专利 ≥ 20 项 | 非学生可控，无佐证 | 改为"完成 M 家企业/科研机构的访谈记录（附纪要）" |
| M5 | 匹配准确率 ≥ 85% | **未说明如何验证**（无测试集、无标注方法、无评测流程），最可能被追问 | 构建标注测试集说明评测方法；或改为"经 K 位植保专家评审，方案一致率 ≥ X%" |
| M6 | 并发 ≥ 1000 人、加载 ≤ 2 秒 | 无实测数据 | 提供实测报告，或删除 |

> 原则：**能被验证的小数字，胜过无法验证的大数字。**

## 七、与小程序原型的衔接

主线已定为"科普 + 反馈采集"，据此给出范围草案（**待策划确认，本文档不实施**）：

### 7.1 本期范围（2026-10-02 确认）

以 [01-一期范围.md](01-一期范围.md) 为**唯一开发依据**：权威除草剂数据 + 规则推荐 + 语音可达 + 高危强提醒 + 个人中心。**不含 AI 识别，不含社区。**

> 完整产品设想（含识别、社区、地区推送、语音中台）见 [00-开发思路图.md](00-开发思路图.md)，定位为**长期愿景（三期总览）**，不作为本期施工图——文中假设的团队规模（8-9 人、含全职农技专家）与周期（10-14 周）不适用于本团队。

### 7.2 本期明确不做

AI 识别、农药标签 OCR、社区、地区推送、语音助手 / 方言包、管理后台、在线售药、区域效果报告。

原因与后置安排见 [01-一期范围.md](01-一期范围.md) 第五节。

> 说明："拍照识别"与"语音播报"曾是教师在研讨会上提出的方向；经 2026-10-02 确认，产品以 00-开发思路图为长期愿景，本期只取其中**不依赖 AI 与后端**的部分。

### 7.3 与申报书的差异（必须修订申报书）

一期与申报书存在方向差异，**必须同步修订，否则答辩时作品与申报材料不符**。

核心差异：申报书主张的"使用反馈闭环""除草剂效果区域化报告"本期不做，需降级为二期 / 三期规划。逐条对照表与建议口径见 [01-一期范围.md](01-一期范围.md) 第六节。

### 7.4 其他技术风险

| 编号 | 风险 | 说明 |
| --- | --- | --- |
| T1 | 演示依赖网络 | 答辩现场网络不可控，需准备离线兜底（本地缓存、预置演示路径） |
| T2 | 语音方案未验证 | 测试号不支持第三方插件；方言识别、田间噪声、适老化交互均需实测。**"语音"是本作品最扎实的现实意义抓手，却被写在一句括号里，建议提升为独立创新点并做技术论证** |
| T3 | 数据规模不足 | 科普库若只有少量示例条目，无法支撑"20 种作物、50 种杂草、100 套方案"，需尽早启动内容生产与专家审核 |

## 九、下一步行动建议

1. **对齐会**（最优先）：确认 Q1、Q2、Q9，把"申报书主线 = 小程序范围"锁定。
2. **申报书修订**：压缩市场与经济效益章节；补强技术论证与参考文献；把"未见报道"改为有依据的表述；指标改为可验证项；补全 F1—F6 的形式问题。
3. **仓库安全**：按 Q4、Q12 结论决定仓库公开性；申报材料脱敏或加入忽略规则。
4. **内容先行**：科普内容生产是最大工作量且不依赖开发，可立即启动。
5. **技术验证**：先用最小实验验证"语音播报可用性"与"反馈表单的适老化填写"，再决定是否投入完整开发。
