# 协作规范

## 分支模型

采用轻量级分支模型，`main` 始终保持可运行。

| 分支 | 用途 | 命名示例 |
| --- | --- | --- |
| `main` | 稳定分支，只接受 PR 合入，禁止直接提交 | — |
| `feature/*` | 新功能开发 | `feature/plant-recognition` |
| `fix/*` | 缺陷修复 | `fix/tts-crash` |
| `docs/*` | 文档变更 | `docs/env-guide` |

> 建议在 GitHub 仓库设置中开启 `main` 分支保护：禁止直接 push，要求 PR 通过至少 1 人评审。

## 日常流程

```bash
# 1. 同步主干
git checkout main
git pull

# 2. 开分支
git checkout -b feature/plant-recognition

# 3. 开发并提交
git add .
git commit -m "feat(capture): 支持相册选图与图片压缩"

# 4. 推送并开 PR
git push -u origin feature/plant-recognition
```

PR 要求：

- 标题与提交信息风格一致
- 描述写清「改了什么 / 为什么 / 怎么验证」
- 至少 1 人评审通过后再合并，优先使用 Squash merge 保持 `main` 历史整洁

## 提交信息规范

格式：`<type>(<scope>): <subject>`

| type | 含义 |
| --- | --- |
| `feat` | 新功能 |
| `fix` | 修复缺陷 |
| `docs` | 文档变更 |
| `style` | 格式调整（不影响逻辑） |
| `refactor` | 重构（不新增功能、不修缺陷） |
| `perf` | 性能优化 |
| `chore` | 构建、依赖、配置等杂项 |

scope 建议取值：`index` / `capture` / `result` / `history` / `api` / `mock` / `tts` / `docs`。

示例：

```
feat(result): 结果页增加语音播报按钮
fix(tts): 修复连续播报时的串音问题
docs(readme): 补充真实接口切换说明
```

## 代码风格

- 使用 2 空格缩进、单引号、语句结尾加分号
- 文件名小写，多个单词用中划线：`voice-player.js`
- 组件、页面、工具模块分别放在 `components/`、`pages/`、`utils/`
- 页面只调用 `api/` 暴露的方法，**不要**直接 `require` `mock/`
- 全局样式令牌定义在 `app.wxss`，页面样式只做局部覆盖
- 用户可见文案使用简体中文，避免生僻术语

## 目录归属约定

> 当前仓库只有最小可运行壳，`components` / `api` / `utils` / `config` / `images` 等目录随功能开发逐步建立，新增后请同步更新 `README.md` 的目录结构。

| 要新增的内容 | 放在哪里 |
| --- | --- |
| 新页面 | `miniprogram/pages/<name>/`，并在 `app.json` 的 `pages` 中注册 |
| 可复用 UI | `miniprogram/components/<name>/` |
| 后端接口调用 | `miniprogram/api/` |
| 假数据 | `miniprogram/mock/` |
| 通用工具 | `miniprogram/utils/` |
| 环境开关与常量 | `miniprogram/config/index.js` |
| 图片资源 | `miniprogram/images/`（命名见该目录 README） |

## 禁止事项

- 直接向 `main` 推送
- 提交 `project.private.config.json`、`.env`、密钥文件
- 在页面中硬编码病害/农药知识内容（应放在 `mock/` 或后端）
- 提交 `node_modules`、日志、编辑器本地配置
