# 快速开始：一台干净的 Windows + 一个开发者工具

面向另一台 Windows 机器上的一个人：机器上只装了 Node 和微信开发者工具，从零把演示栈跑起来，最后在小程序模拟器里点得动「微信登录」。

八步，大约 20～30 分钟，一半时间花在装 PostgreSQL 和开发者工具上（那两步是安装向导，跟着点即可）。

**先读这两条边界，再动手：**

1. **本机演示政策不是生产核验。** `--demo` 写进去的隐私政策、接收方、三个功能开关，是**只覆盖本机演示栈**的演示档数据。它不构成合规结论，不能当生产核验证据，也不能拿它对外说"隐私政策已审"。
2. **首页的「未核实」标签是设计。** 演示资料没有第三方核验来源，卡片上就显示「未核实」。这是刻意的提示，不是 bug，不要为了让截图好看去改它。

另外：本篇只写**键名**，任何位置都不写密钥值；凭据值只存在于你自己机器上的凭据文件和生成出来的 env 文件里。

## 八步地图

| 步 | 做什么 | 命令（在仓库根跑） |
| --- | --- | --- |
| 1 | 装 PostgreSQL 17 | 安装向导；仓库自带 `.pg17` 可跳过 |
| 2 | 准备凭据文件 | 手工放一份 `credentials.local.json` |
| 3 | 凭据 → env 文件 | `npm run demo:env-up -- --from … --out …` |
| 4 | 起演示栈 | `npm run demo:up -- --demo --seed-demo --port 38110 --env-file …` |
| 5 | 生成小程序副本（直接落在仓库外） | `npm run demo:project -- --config config\debug.local.json --no-urlcheck --out …` |
| 6 | 导入开发者工具 | 开发者工具界面操作 |
| 7 | 点「微信登录」 | 模拟器里点 |
| 8 | 按演示脚本走一遍 | 看 `docs/demo/演示脚本.md` |

全流程固定用 **API 端口 38110、PG 端口 55510**。理由是既有演示口径（`docs/demo/本地演示-stack.md` 与 `docs/demo/演示脚本.md`）都按 38110 写死，演示脚本第 5 步会检查副本里是不是 `http://127.0.0.1:38110/api/v1`。要换端口就三处一起换：`demo:up --port`、`demo:status`/`demo:down --port`、小程序配置里的 `port` 与 `apiBaseUrl`。

## 1 装 PostgreSQL 17（本仓自带 PG 可跳过）

演示栈自己 `initdb` 一个簇、自己起停，**不需要**注册 Windows 服务、也不需要记住超级用户密码。它只要 PostgreSQL 17 的二进制目录（`initdb.exe` / `pg_ctl.exe` 在那儿）。

**命令**

先看这台机器上有没有现成的：

```powershell
Test-Path "E:\GengYunCommander\.pg17\pgsql\bin\initdb.exe"
```

- 输出 `True`：仓库边上已经带了一份 PG，第 4 步不用加 `--pg-bin`，直接跳下一步。
- 输出 `False`：装一个 PostgreSQL 17（EnterpriseDB 安装包即可，安装时**不用**勾 Stack Builder），记下它的 `bin` 目录，第 4 步加 `--pg-bin "<安装目录>\bin"`。

**应看到的输出**

`True`，或者安装完成后 `& "<安装目录>\bin\initdb.exe" --version` 打印出 `initdb (PostgreSQL) 17.x`。**必须是 17**：迁移脚本与既有演示栈都按 17 的口径验证过。

**失败时先看哪里**

- `--version` 报找不到命令：路径里有空格，PowerShell 里要用 `& "…"` 调用，别直接裸写。
- 装成了 16 或 18：别混用。演示栈会把 `pg_ctl` 的报错原文打出来；版本不对时优先装 17，不要改仓库里的迁移。

## 2 准备凭据文件

**命令**

在一台已经有真实凭据的机器上，把凭据文件放到新机器的这个位置（路径可自选，但本手册后面按这个写）：

```
E:\GengYunPrivate\credentials.local.json
```

它是 **UTF-8** 的 JSONC：允许 `//` 行注释、`/* */` 块注释、尾逗号（第 3 步的工具有自己的 JSONC 解析器，不会因为注释报错）。需要的键名：

| 键名 | 用途 |
| --- | --- |
| `appid`、`appsecret` | 微信小程序的 AppID 与密钥，必须与第 5 步副本里的 AppID 同号 |
| `objectStorage.Endpoint`、`.Bucket`、`.AccessKey`、`.SecretKey` | 对象存储四件套（也认扁平的 `objectStorageEndpoint` 这类写法） |
| `sessionSigningKey` | 会话签名钥匙 |
| `deletionLedgerKey` | 注销台账钥匙 |
| `deepseekApiKey` | 识别服务（视觉模型）的 key |

可选：`mediaObjectRefKey`（媒体对象引用钥匙）。**不写也行**，第 3 步会生成一把并写进输出文件的注释里。凭据里还有 `tencentSecretId` / `tencentSecretKey` / `tokenhubApiKey` / `databaseUrl` 之类的键也没关系，工具只取它认识的那些，其余不读。

**应看到的输出**

文件存在、能用记事本打开且中文注释不乱码：

```powershell
node -e "const t=require('node:fs').readFileSync('E:\\GengYunPrivate\\credentials.local.json','utf8');console.log('chars',t.length,'hasBOM',t.charCodeAt(0)===0xfeff)"
```

期望 `hasBOM false`。

**失败时先看哪里**

- 打出来是乱码：文件被存成了 GBK。第 3 步的工具会先按 UTF-8 读、失败再按 GBK 读，两边都失败才报错；但这属于碰运气，正确做法是把它另存为 UTF-8。
- `hasBOM true`：某些编辑器会加 BOM。BOM 本身不影响第 3 步（工具会剥掉），但**别把带 BOM 的 JSON 存成小程序配置**，那段见第 5 步的坑。
- 缺键：第 3 步会 fail-closed，一次性列出缺哪些键名并以 exit 2 退出——按清单补齐再跑，别一边补一边猜。

## 3 凭据 → env 文件（`npm run demo:env-up`）

把凭据 JSONC 翻译成 API 认识的那 13 个 env 名，写成一个 `KEY=VALUE` 的 env 文件。这一步是以前手工做的那个动作（拿 GBK 读凭据、手抄 6 个键），现在一条命令。

**命令**（在仓库根，路径都写绝对路径）

```powershell
npm run demo:env-up -- --from "E:\GengYunPrivate\credentials.local.json" --out "E:\GengYunCommander\.pg17\demo-real.env"
```

三条硬规矩，工具会替你守：

- `--from` **只读**。工具不会改你的凭据文件，一个字节都不会。
- `--out` 必须在**仓库目录之外**。写在仓库里会被直接拒绝（exit 1）——那是密钥，不能进版本库。
- 默认**拒绝覆盖**已存在的输出文件（exit 1，一个字节不动）。确实要重写加 `--force`；加了 `--force` 它会沿用旧文件里的 `MEDIA_OBJECT_REF_KEY`（换钥匙会让已经存进对象存储的媒体解不开）。

**应看到的输出**

```
✓ 已写出 13 个键 → E:\GengYunCommander\.pg17\demo-real.env
  来源：E:\GengYunPrivate\credentials.local.json（utf-8；只读，没有改动它）
  生成：MEDIA_OBJECT_REF_KEY（本次新生成）
  下一步：npm run demo:up -- --demo --seed-demo --env-file <上面这个路径>
```

行数固定，**不会打印任何值**。`生成：` 那行只列键名：通常是 `MEDIA_OBJECT_REF_KEY`；如果你在凭据里自己写了 `mediaObjectRefKey`，这行会写「无（所有键都来自凭据文件）」。

**失败时先看哪里**

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| exit 2，`缺 N 个键` + `- ENV名 ← 源键名` 清单 | 凭据里没这些键 | 按清单补键名，值自己填；清单只给键名，不会回显值 |
| exit 2，`无法按 UTF-8 或 GBK 解码` | 文件不是这两种编码 | 另存为 UTF-8（无 BOM） |
| exit 2，`第 N 行附近解析失败` | 引号/括号不配对（工具故意不打印 JSON 原文，怕把值带进日志） | 用编辑器定位到那一行看 |
| exit 1，`已存在` | 上次已经生成过 | 常规重跑加 `--force`；只想换凭据来源时先删旧文件 |
| exit 1，`不能在仓库内` | `--out` 指到工作树里了 | 换到 `E:\GengYunCommander\.pg17\` 这类仓库外目录 |
| exit 1，`必须是绝对路径` | 用了相对路径 | 两个参数都写全路径 |

生成的 env 文件权限会尽量收成"仅本人可读写"（`0600`）。Windows 上这一位不一定生效，所以还是别把它放进同步盘。

## 4 起演示栈（`npm run demo:up`）

**命令**

```powershell
npm run demo:up -- --demo --seed-demo --port 38110 --env-file "E:\GengYunCommander\.pg17\demo-real.env"
```

- `--demo`：开三个功能开关（投稿 / 具体除草剂输出 / AI 识别），写两条演示隐私政策（`media_processing`、`external_inference`）和一个演示接收方。幂等，重复跑不会叠加。
- `--seed-demo`：灌 8 条演示资料（非生产数据），首页才有卡片。
- 端口：API 38110、PG 默认 55510。PG 端口冲突就加 `--pg-port`。
- 第一次跑会 `initdb` 一个新簇，比后面慢；数据、日志、pid 全在仓库外（默认 `<仓库上级>\.pg17\demo-stack`）。

**应看到的输出**

九段进度（`[1/9]` 到 `[9/9]`），关键是末尾这几行：

```
[9/9] 启动 API
  ✓ /health → 200 ok（database=ok, mode=real）

演示栈已就绪：API http://127.0.0.1:38110（real），PG 127.0.0.1:55510

下一步（微信开发者工具）：
  1) 准备小程序工程：
       node tools/prepare-wechat.mjs local --config config/debug.local.json
     其中 apiBaseUrl 写 http://127.0.0.1:38110/api/v1，port 写 38110，bindHost 写 127.0.0.1
```

末尾「下一步」那两行是 `demo-stack` 自带文案（写死在工具里，本次不改）：它给的是默认路径，拷贝时记得按第 5 步加上 `--out`，把副本生成到仓库外。

看到 `健康：GET /health → 200` 才算起来了。自己再确认一次：

```powershell
curl.exe -s -o NUL -w "%{http_code}`n" http://127.0.0.1:38110/health
```

期望 `200`。（`/api/v1/health` 是 404，健康检查在根路径。）

**失败时先看哪里**

工具用退出码区分阶段，失败时先对号：

| 退出码 | 阶段 | 先看 |
| --- | --- | --- |
| 2 | 端口被占 | `npm run demo:status`；或换 `--port`（记得第 5 步配置同步改） |
| 3 | PG 起不来 | 打印出来的 `pg.log` 尾部。最常见两种：端口被别的簇占了；`could not bind … Permission denied` —— 这是 Windows 的保留端口段，`netsh interface ipv4 show excludedportrange protocol=tcp` 看一眼，换一个不在段内的 `--pg-port` |
| 4 | 迁移失败 | `state-dir\migrate.log`；别手改迁移，先确认 PG 版本是 17 |
| 5 | 种子失败 | `state-dir\seed.log` |
| 6 | API 起不来 | `state-dir\api.log` 尾部；多半是 env 缺键（`ConfigError` 会点名键名） |
| 7 | 健康没到 200 | 同上，先看 `api.log`；`/health` 报 `database` 不通说明 PG 停了 |

排查三件套：`npm run demo:status`（进程/端口/健康）、`npm run demo:logs -- --lines 50`（API 日志尾）、`npm run demo:down`（收工，日志留着）。

## 5 生成小程序副本（`npm run demo:project -- --out …`）

**为什么要有副本**：`miniprogram/` 是共享工程，`runtime.js` 里写着 disabled 原文。演示要连本机 API，就得生成一份**隔离副本**，只改副本，共享工程一个字节不动。

**命令**（两步，都在仓库根）

第一步，写本地配置（只改端口，`apiBaseUrl` 必须带 `/api/v1`；客户端是拿它直接拼 `/auth/...` 的，漏了前缀会一路 404）：

```powershell
node -e "const fs=require('node:fs');fs.writeFileSync('config/debug.local.json',JSON.stringify({mode:'local',bindHost:'127.0.0.1',port:38110,apiBaseUrl:'http://127.0.0.1:38110/api/v1'},null,2)+'\n')"
```

第二步，生成副本到仓库外（`--out` 是**根目录**，副本名仍固定 `wechat-local`；`--no-urlcheck` 只把副本的 `setting.urlCheck` 写成 `false`，省掉开发者工具里手勾）：

```powershell
npm run demo:project -- --config config\debug.local.json --no-urlcheck --out "E:\GengYunCommander\.pg17\demo-project"
```

**应看到的输出**

```
LOCAL import root: E:\GengYunCommander\.pg17\demo-project\wechat-local
Local client base (runtime.apiBaseUrl): http://127.0.0.1:38110/api/v1 ; …
生成副本 AppID：wx…（来源：共享工程 project.config.json 默认值）
服务端必须同号：WECHAT_APP_ID 必须等于上面这个 AppID …
```

`LOCAL import root` 打的就是最终目录，直接拿去导入开发者工具——**不用再挪**。

**为什么 `--out` 必须在仓库外**：副本里有上千个 `*.js`，和仓库里的同名文件混在一起，会让文档锚点闸门把单义锚点判成多义或失效。实测：副本留在 `.local\` 时，`node tools/verify-doc-anchors.mjs --strict --symbol=strict --symbol-coverage=strict --symbol-coverage-verification=strict --scan docs` 会从 PASS 变 exit 1；挪到仓库外以后恢复 PASS。所以工具把这件事故变成一次参数错误：`--out` 落在仓库树内直接拒绝（退出码 2，报错原文点名文档锚点闸门），**一个目录都不建**。

**失败时先看哪里**

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| `--out 不能落在仓库树内` | 输出根目录在仓库里 | 换成仓库外的位置（如上面那句），重跑 |
| `Output already exists` | 副本目录已存在，工具拒绝覆盖 | 删掉那个确切目录重跑，或加 `--force`（只删 `--out` 根目录下这一个目录） |
| `Unexpected token '\ufeff'` / `Unexpected token '﻿'` | 配置被存成了带 BOM 的 UTF-8（PowerShell 的 `Set-Content -Encoding utf8` 会加 BOM） | 用第一步那句 `node -e` 重写；或用编辑器「UTF-8 无 BOM」另存 |
| `apiBaseUrl 必须以 /api/v1 结尾` | 漏了前缀 | 改成 `http://127.0.0.1:38110/api/v1` |
| `共享工程必须 …urlCheck=true` 之类拒绝生成 | 有人改过共享工程的 `project.config.json` / `runtime.js` | 那是防呆，不是 bug：`git checkout -- miniprogram/config/runtime.js project.config.json` 后重跑 |
| AppID 对不上 | 副本 AppID ≠ 凭据里的 `appid` | 加 `--appid wx…` 换副本 AppID，或换凭据；两者必须同号 |
| 副本里报 `MODULE_NOT_FOUND` | 旧版脚本按清单逐个拷文件，新增的 `utils/*.js` 会漏 | 现在整树复制，不会漏；如果你手里的副本是旧的，重跑这一步 |

## 6 导入开发者工具

**命令**

打开微信开发者工具 → 导入项目 → 目录选第 5 步打印的那个 `LOCAL import root`：

```
E:\GengYunCommander\.pg17\demo-project\wechat-local
```

AppID 就用它自己读到的（副本里已经写好）。导入后确认「详情 → 本地设置 → 不校验合法域名…」是勾选状态（用了 `--no-urlcheck` 就该是）。

想用命令行开（路径**必须**绝对路径）：

```powershell
& "<开发者工具安装目录>\cli.bat" open --project "E:\GengYunCommander\.pg17\demo-project\wechat-local"
```

**应看到的输出**

模拟器把首页渲染出来（可能先是「暂无资料」，如果第 4 步没加 `--seed-demo`），控制台里能看到请求打到 `http://127.0.0.1:38110`。

**失败时先看哪里**

- 报"项目路径不存在"：`cli.bat` 对相对路径会报 code 10 而**退出码仍是 0**，别被退出码骗了，路径写绝对路径。
- 首页一直转圈或报域名不合法：回「详情 → 本地设置」看域名校验是否真的关掉了；再回 `npm run demo:status` 看服务在不在。
- 控制台 404：看副本里 `miniprogram/config/runtime.js` 的 `apiBaseUrl` 是不是带了 `/api/v1`。

## 7 点「微信登录」

**命令**

模拟器首页点「微信登录」，扫码授权。

**应看到的输出**

登录成功、回到首页（带 `--seed-demo` 时首页有演示卡片，卡片上标着「演示资料·非生产数据」，未核验的标「未核实」）。失败时会弹一个错误码/提示。

**失败时先看哪里**

按这个顺序卡：

1. AppID 与 `WECHAT_APP_ID` 不同号 → 服务端 `code2session` 必然失败。第 5 步打印的 AppID 与凭据里的 `appid` 必须一致。
2. `appsecret` 不是这个号后台生成的 → 微信侧返回 appid/secret 不匹配类错误，看 `npm run demo:logs -- --lines 50`。
3. 你的微信号没有这个 AppID 的「小程序项目成员」资格 → 用测试号（第 5 步输出里有测试号入口）；测试号 openid 与正式号不互通，它只能演示，不能当正式验收证据。
4. 服务端 503：识别/媒体域没接上。`--demo` 已经把媒体域真实接线批过了；还 503 就看 `api.log` 里点名的键名。

**命令**

打开 `docs/demo/演示脚本.md`，从第 1 步顺着走。

**应看到的输出**

脚本每一步都写了「应看到」和「出问题找谁」。它假设 API 在 38110、小程序副本的 `runtime.js` 指向 `http://127.0.0.1:38110/api/v1` —— 和前七步一致。

## 日常命令速查

| 事 | 命令 |
| --- | --- |
| 凭据 → env | `npm run demo:env-up -- --from <凭据> --out <env 文件>` |
| 起（演示档 + 资料） | `npm run demo:up -- --demo --seed-demo --port 38110 --env-file <env 文件>` |
| 状态 | `npm run demo:status -- --port 38110` |
| 日志 | `npm run demo:logs -- --lines 50` |
| 停（留数据） | `npm run demo:down -- --port 38110` |
| 清空重来（删数据） | `npm run demo:reset -- --yes` |
| 小程序副本 | `npm run demo:project -- --config config\debug.local.json --no-urlcheck --out <仓库外的根目录>` |

名词：**API** 是本机接口服务；**PG** 是 PostgreSQL；**state-dir** 是数据/日志/pid 的存放处（仓库外）；**real / stub** 是连真数据库 / 只验证链路（stub 下首页必然 503，这是契约不是故障）。

## 哪些键是工具生成的

只说键名：

- `MEDIA_OBJECT_REF_KEY` —— 凭据里没有就由 `demo:env-up` 生成（32 字节随机数的 64 位十六进制），并在输出文件里那句注释说明"本机演示用、生产须单独生成"。凭据里写了 `mediaObjectRefKey` 就用你的。
- `DATABASE_URL` —— 由 `demo:up` 自己生成，指向它刚起的那个簇；env 文件里写了也会被覆盖。
- `SESSION_SIGNING_KEY` / `DELETION_LEDGER_KEY` —— `demo:env-up` 从凭据里取；万一 env 文件里没有，`demo:up` 会自己生成并存到 `state-dir\secrets.env`（仅本人可读）。
