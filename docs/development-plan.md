## 1 范围、依据与监工职责

需求决定功能和验收，本文决定实施顺序与契约。用户已确定微信小程序；首版识草／标签 OCR、科普、真实 AI 社区、普通话 ASR 向大模型提问、TTS、收藏历史、应用内消息和独立网页后台均必交。首版仅比赛演示且依赖网络，人工审核板块为空；二月才做使用提醒反馈、人审、专家预警、报告及展示对接与支付沙箱。

本轮核查了原生微信示例、植物识别小程序、服务端 AI 聊天、杂草数据集和自动化测试项目，具体提交与采用边界见[参考记录](github-project-references.md)。参考项目的技术栈、准确率、地区及商业功能不改变已确认需求，不用通用“病害识别”替换识草查药。

Codex 的职责是监工：核对大方向、架构、具体实现与证据，审查协作者 PR，通过后合并 main。协作者实现并提交可复现材料。每 12 小时自动巡检或用户消息触发，按[PR规范](pr-review-policy.md)验证当前 SHA；文档、工程壳和 CI 绿灯不等于应用完成。本次创建／调整的远端任务只到初版，二月开发包暂不发布 issues。

## 3 数据、接口与异步契约

### 3.1 对象与读写边界

| 模块 | 至少要定义的对象／字段 | 必须维持的边界 |
| --- | --- | --- |
| 身份与档案 | user、session、role、single_profile、crop_id、region_code | wx.login的code在服务端交换身份；客户端不能传角色或指定openid。游客仅主页，所有其他API校验会话及归属，后台独立登录 |
| 来源资料 | species、crop、herbicide_registration、formulation、source_version、source_kind、validity、review_status、conditions | 登记号＋成分／含量／剂型匹配；真实／种子／模拟可查，来源失效或冲突不进入具体用量依据 |
| 媒体任务 | media_id、owner、purpose、mime、bytes、visibility、expires_at；job、revision、idempotency_key、provider_version | 私有上传不自动公开；签名访问短效，建议5分钟并可配置；完成前后重查归属／用途／账号状态，版本过时结果不可覆盖 |
| 识别与问答 | recognition、OCR原文／校正／匹配分别存；conversation、turn、ASR原文／确认文本、citation_source_ids、check_result | 原始预测与用户校正分开，私有会话不自动发社区；引用来自检索证据，用量卡片确定性渲染，检查后才显示／朗读 |
| 社区与审核 | post、comment、revision、media_refs、audit_job、decision、reason、visibility、report | 每版本先审后发，文字图片均检查；修改进入新审核，旧结果不能放行新内容；失败保持隔离 |
| 收藏消息 | favorite目标类型／版本、recognition_history、message、read_at、target_ref | 去重，读取时重新检查可见性及来源有效性；下架或删除对象不从旧引用重新公开 |
| 隐私与删除 | consent用途版本、recipient、export_ref、deletion_request、module_handler、tombstone、third_party_status | 拒绝／撤回／注销阻断新外发和在途回写；在线7日备份30日；第三方请求与完成分开，恢复先重放删除清单 |

GY-I01交数据字典、关系与索引、迁移版本及状态枚举，GY-I03交四作物八杂草与标签资料样例。默认查询使用登记号／中文药名词典和结构化过滤；向量检索是可选适配，只有增加有来源问答评估收益且不破坏条件过滤才引入。

### 3.2 HTTP接口组

下表是GY-I01落实OpenAPI的分组，不是已经可调用的地址。统一前缀/api/v1，实际路径和schema经契约PR冻结。

| 接口组 | 所需行为与权限 |
| --- | --- |
| public/home；auth/wechat、session、logout | 仅主页公共内容可游客访问；服务端微信身份交换、会话撤销、管理员登录独立 |
| me/profile、consents、account/deletion | 单地区作物档案、用途同意撤回、注销幂等；定位仅客户端即时换地区，不传原坐标 |
| media/uploads、jobs/{id} | 校验用途／媒体真实类型、任务归属、分页／轮询／取消；对象不存在或非本人不泄露内容 |
| knowledge、herbicides、registrations/verify | 来源版本、结构化条件、登记冲突与不足原因；前后端不重复药剂安全算法 |
| recognitions、ocr、speech/transcriptions、speech/synthesis | 六类服务均经适配器；录音限额、原始转写与编辑确认分开；合成仅已检查文本 |
| conversations、turns | 确认文字可直接提问；语音经ASR后用同一接口，检索→生成→检查完整结果，不输出未检查流 |
| posts、comments、likes、reports | 登录写入、版本重审、AI隔离、可见性读取；首版没有人审任务接口 |
| favorites、history、messages | 归属、游标分页、去重／取消／已读、引用失效状态，不发送首版微信外推 |
| admin/sources、accounts、jobs、feature-flags、audit-events | 服务端最小权限与审计；来源／账号／任务管理、危险功能停用，无首版假评审、专家或真实预警 |

分页使用有上限的游标，写接口使用幂等键和版本检查；HTTP状态401／403／404／409／422／429／503与业务错误码对应未登录、无权限、失效、冲突、输入不足、限额、服务不可用。供应商超时单独编码，前端保留可重试输入；不要把所有失败返回200“成功”。

### 3.3 状态与竞态

任务至少queued→running→succeeded／uncertain／failed／timed_out／cancelled，结束状态不可由旧回调复活。领取任务用持久租约，重试有上限、退避和幂等键；普通API限流与供应商额度独立。多次提交不重复计费或创建公开内容，超过重试限额返回明确失败，不无限重试。供应商不支持幂等时记账并避免自动重复有副作用请求。

社区审核至少pending→approved／rejected／quarantined，并与内容revision绑定；AI无结论和失败进入隔离。规则过滤不由模型或后期多数投票解除。资料有效性、对象可见性和用途授权既在任务执行前校验，又在完成保存／公开读取时校验，防止注销与下架竞态。

删除清单与恢复流程不得依赖可被恢复覆盖的旧业务数据库状态；保存最小必要的不可逆或受控删除标记，不保留能恢复账户身份的公开映射。首版不开启用户数据训练；以后开启前额外验独立同意、第三方可控性、样本及模型谱系、受影响模型停用、删除和重训重评。
