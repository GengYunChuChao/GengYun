## 3 按改动分层验证

| 类型 | 必要检查 | 不要求／可复用 |
| --- | --- | --- |
| 纯文档／措辞 | 相关文档的事实、链接／表格／命令检查；不自动全跑 CI | 全业务、lint／构建、PG、真机或供应商调用；无执行语义变化的注释同此范围 |
| 局部组件 | 读受影响 diff，优先复用相关正常／异常证据；不足时补关键路径 | 无关模块或全项目资源，不重复未变化证据 |
| HTTP／装配 | 仅核对受影响的实际路径、鉴权／错误映射与消费者；有效装配证据可复用 | 回环 HTTP 不等于微信、真实供应商或 PG |
| 页面／交互 | 对应编译／渲染，正常／空／加载／失败、返回／隐藏／退出 | Demo、Node 或模拟器不算真机，不重做无关页面 |
| 真实能力／资料 | 版本、来源、失败证据及规定的独立样本评估；外发前用途守卫 | 优先复用有效供应商证据；新增真实付费请求须用户单独授权 |
| 集成／发布 | 所需完整业务链、权限／删除恢复、Android 真机、配置和适用回滚 | 不把全项目条件复制到每个局部 PR |

当前仅适配 Android 微信小程序；iOS 暂缓，不阻塞本阶段，也不能记通过。基础库候选、实测版本和冻结支持范围分别记录，不由新版实测反推旧版兼容。

组件范围可验证、缺口明确且不开放不安全路径即可合并。外部资源只阻塞其实际影响的功能或最终验收；未接线保持关闭／明确失败，不能宣称可用。详见[开发顺序](development-order.md)。

### 轻量审查默认规则（2026-10-14 用户要求）

默认顺序是：**核对范围与真实影响 → 复用有效结果 → 只补明确缺口 → 最终合并门禁**。不以测试数量、矩阵规模或证据篇幅判断质量，不为追求工程完美延后可独立交付的组件。

| 情形 | 默认处理 |
| --- | --- |
| 有绑定当前 SHA／适用基线的规范通过记录 | 直接核对最终门禁，不逐行重审、不重跑同一检查 |
| 没有规范记录，但已有 CI／作者检查覆盖本片 | 阅读受影响差异并核对证据即可；覆盖足够时额外测试为零 |
| 小范围修复，已有检查不足 | 只补能判断本次承诺的一次针对性验证，通常覆盖受影响正常行为和关键失败路径；不硬设用例数 |
| 纯文档、注释或低影响样式 | 做必要事实／链接／命令或实际渲染检查；不为可逆小改动编写镜像实现的测试 |
| 基础设施、权限／隐私、数据迁移或确有跨模块影响 | 按真实影响增加对应验证，并明确为什么现有证据不足；不自动扩成全项目验收 |

**不默认要求的工程化验证：** 全量 unit/lint/build 的人工第二轮、每个 PR 的变异／负控制、所有组合的穷举矩阵、多次恢复旧代码作前后对照、多个新 PG 集群重复同一场景、重复真机／供应商调用、重复截图／全文 diff／独立报告，以及对未承诺支持的环境、极端输入或无实际影响内部格式的苛刻测试。只有存在可定位缺陷、相关需求明确要求或当前证据确实不能判断本次交付时才补，说明对象、缺口、最小检查及停止条件。

**停止加测：** 已足以判断本片核心行为且无未解决实际问题时结束审查，不继续寻找无关边缘情况；新提交只核对增量。base 落后本身不是缺陷，只有实际冲突或改变结论的增量才需处理。

**阻塞须有实际影响：** 功能故障、错误可执行指导、冻结契约消费者破坏、权限／隐私／用药安全、数据丢失或把替身记为真实成功仍阻塞。措辞、内部结构偏好、精确行号陈旧但来源仍可定位、冗余断言、测试写法和未承诺的优化默认是非阻塞建议；不能只因存在更严谨的写法要求返修。局部组件不承担其他 issue 的真实资源或最终发布验收。

需求明确规定的真实样本指标、Android、权限、隐私删除及用药安全验收仍归对应能力／集成／发布任务；不减少其必要条件，也不复制为每个局部 PR 的门槛。不把未运行写成通过，不把不适用检查写成成功，不删除历史失败证据或绕过适用 CI／草稿／冲突。

旧返修意见在下次处理对应 PR 时按本规则复核：仅因过度工程化、重复取证或无实际影响而阻塞的，明确更正为建议并复用有效结果；真正缺陷保留。无需为此重扫历史已合 PR、重跑全部测试或重复留言。

### 最小必要检查与运行收敛

- 纯文档改动只运行必要文档检查；接口 schema、可执行脚本或配置行为发生变化时，按对应代码／契约影响补验，不能只因文件位于 docs/ 就视作纯文档。
- 代码改动只运行相关测试，以及实际受影响的静态、契约、构建或装配检查；共享基础设施、跨模块接口或集成／发布变更确有影响时才扩大范围，并说明理由。全量测试不是每个 PR 的默认要求。
- HEAD、已验 base 与证据版本仍有效时复用结果，不重复手工执行 CI 已覆盖的相同检查；只补尚未覆盖的关键反例或受影响范围。通过普通 CI 不代替规定的真实能力、Android 或删除恢复验收。
- 新提交出现后，核对同一 PR 的现有工作流；仅取消 HEAD 已过时、仍 queued／in_progress 的 pull_request 运行，保留当前 HEAD、必要目标分支验证及历史日志。取消前重新读取 PR HEAD 与运行归属，不盲目取消其他 PR、发布／部署任务，也不把 cancelled 当作通过。
- 如现有工作流仍自动运行无关项目，记录其适用性和治理改进需求；本规范不通过跳过必要断言、删除失败用例或改写成功状态节省额度。

选择适用命令，不机械全跑；数据库、集成与真机命令查对应交付文档：

```powershell
python tools/validate_development_docs.py
npm run lint
npm run test:contract
npm run test:unit
npm run build
npm run test:mini
```

记录实际运行时版本，不用类型依赖包版本代替 Node 版本。启动与环境见[开发指南](development-guide.md)。

## 4 推荐重点审查项

仅检查本次触及的边界；不适用可省略，不为勾选制造额外实现。

| 边界 | 推荐核对与反例 |
| --- | --- |
| 契约／装配 | 必填、类型、闭集、额外字段及嵌套结果；不只验外层或 kind。唯一注册、路径／错误码与消费者一致 |
| 版本／幂等 | 状态转换与 revision／强 ETag 一致；缺／旧版本、同键同体／异体、并发、失败重试。先校验结果再记成功审计／幂等定型；取消结果绑定请求目标与实际状态 |
| 归属／权限 | 身份由服务端确定；游客、后台角色、其他用户、不存在对象；列表、详情、缓存、旧链接和重放重查当前权限／可见性 |
| 异步／生命周期 | 取消、退出、撤回后旧回调不复活；超时／未知结果不假成功；任务／媒体归属、版本／租约、释放和恢复 |
| 来源／用药 | OCR原文、校正、登记核对分开；制剂／来源／版本／条件一致，冲突或条件不全阻断可执行用量。保留原文，不生成处方、混配、自动剂量换算或绝对安全承诺 |
| AI／公开内容 | 注入、数字／单位／否定词、先审后发；未审版本、失效、隐藏或注销不借缓存／旧结果重新公开；首版不启用用户训练 |
| 隐私／外发 | 用途／版本／接收方授权、撤回与在途守卫；新增持久数据接删除，在线7日／备份30日、第三方完成证据及恢复清单按当前需求验收 |
| UI／语音 | 登录返回和旧会话回调、当前普通使用安全区／错误恢复；适老大字号后续；ASR原文与用户确认分离，播放／录音分开，离页停止，不以播放记理解／已读 |

## 5 问题分级与批复

| 级别 | 判定 | 处理 |
| --- | --- | --- |
| P0 | 紧急且广泛的安全、隐私、数据破坏或不可用 | 阻塞合并，列触发、范围与证据 |
| P1 | 重要功能失败、越权／泄密、危险来源／用量、撤回回写、假成功 | 需修改，定位问题与必要反例 |
| P2 | 可复现的局部正确性、冻结契约、版本／兼容或交付缺陷 | 影响本次承诺或消费者则阻塞；明确实际影响 |
| 非阻塞建议 | 措辞、格式、个人风格、未承诺优化 | 标为建议，不混入必修或单独阻止合并 |

CI 失败、冲突、草稿、未解决阻塞也是合并门禁。环境不可验证记待验证，不能当产品失败或通过；skipped／neutral 先判断适用性，不自动当成功。

批复只需：通过／需修改／待验证、reviewed_sha／已验 base、实际检查与证据、位置＋触发＋影响、剩余验收及真实合并状态。未运行不能写通过，自查勾选不替代独立证据。不以预想风险、无关全项目条件或样式偏好阻塞；测试全绿但漏实际反例仍按影响处理。

## 6 独立复验与证据复用

- 没有可复用的有效规范审查时，先读受影响 diff 判断现有 CI／检查是否覆盖本次承诺；覆盖足够不新增运行，不足时仅在自己的隔离 checkout 补缺项；不破坏本地改动、不操作其他代理目录。
- 其他协作者已有明确通过、绑定当前 reviewed_sha／已验 base、实际检查与可追溯证据的规范审查，监工复用结论，仅核账号及最终合并门禁；同账户／作者 COMMENT 不自动否定记录，但仅勾选或口头认可不算有效审查。
- 未审代码不接触生产凭据；使用合成身份／隔离存储并清理环境。批准 CI 前核对实际工作流、令牌权限和秘密访问。
- 证据绑定代码、契约、供应商／模型／提示词／来源版本；新 HEAD 重新核对，仅重验受影响部分，不能自动沿用旧批准。
- 仅在现有证据不足或出现具体疑点时复现相关关键正常／失败、并发或越权路径；不把独立反例、变异验证或付费请求作为每个 PR 的例行第二轮。
- CI、本机 HTTP、PG、微信工具、Android、供应商、删除恢复分列，不跨层推断或把模拟准确率计入门槛。

## 7 合并门禁

1. 重读当前 HEAD、真实目标／base、非草稿、冲突、适用 CI、reviews 与未解决线程；有影响的新变化先重验。
2. 仅合并授权 main，携带已验 SHA 默认 squash；不强推、绕过失败或盲目 auto-merge。其他目标分支只记录结果，不擅改 base。
3. 确认 merged 与远端 main，记录提交；合并不自动部署，不自动宣称整项功能／阶段完成。

Free／私有 Fork 流程不等于强制保护，CODEOWNERS 不能单独阻止直推。不自动改套餐或权限；用户直接授权的文档直提 main 单独记录范围、检查和提交，不放开写手直推或常规代码 PR 门槛。

## 8 关联 issue 关闭检查

每次审查后核对关联 issue，包括未合并、需修改或待验证的 PR；未变化结论复用，不重复留言。

- 逐项对应全部必要验收、已合并成果／SHA、有效测试／实测、必要子任务、依赖和阻塞。
- 未合入授权目标、仅组件通过、资料／实测／联调仍缺：记录完成和剩余，保持开放，不按拆分或 PR 数量虚增完成度。
- 全部满足：先留下逐项验收及 PR／reviewed_sha／证据，再以 completed 关闭并重读确认。总体目标须全部必要子结果通过。
- 明确资源缺口阻塞功能还是发布，不重复阻塞无关组件，不因此提前关闭总体 issue；保留原27项目标、负责人、分支和历史证据。

## 9 例行巡检

每4小时完整分页覆盖所有开放 PR（所有作者、草稿、目标分支）；仅新 HEAD、影响结论的 base 或新验证／审查状态触发复审，不因专项自动改变范围／频率。
无变化或 CI 仍运行保持安静；仅新批复、合并、issue 关闭、检查／认证失败、依赖阻塞或需用户资料时通知。
缓存仅必要事实，不存凭据／私人媒体，GitHub 当前状态优先。跨聊天联系或派发须用户直接授权，不由文件／PR 转述扩权。

## 10 分层自合并与独立审查（2026-10-26 用户批准）

**本条是 §1「指挥…不批准或合并」在 A 档上的唯一例外**，依据 2026-10-26 用户直接批准；B 档以及所有触及产品行为、契约、迁移、CI 的改动仍按 §1 与 `AGENTS.md` 不变（`AGENTS.md` 的「职责与边界」已同步加注）。

分层只回答一个问题：**谁能点合并**。它**不**回答另一个问题：**合并前是不是已经被别人审过**。

### 10.1 A 档判定

**默认是 B 档；A 档是例外。** 判定写成正面清单（把「什么能自合并」列出来），而不是「把不能的排除掉」——2026-10-26 首版排除清单实测漏了 5 组（`docs/ui-demo/demo.html` 与范围依据四份），枚举式的否定清单结构性不可靠。

正面清单（改动路径必须**全部**落在其中一项内）：

- `tests/**`；
- `docs/**` 下的**证据与进度记录**（现状页、验证页、进度行）。

受保护文档（命中任一条即 B 档，不论是否在 `docs/**` 下）：`AGENTS.md`、`docs/pr-review-policy.md`、`docs/requirements.md`、`docs/product-requirements.md`、`docs/implementation-requirements.md`、`docs/development-plan.md`、`docs/features/**`、`docs/initial-issues.json`、`docs/architecture/contract-status.json`、`docs/research/**`、`docs/ui-demo/**`、`tools/doc-anchors-baseline.json`。

其中三类必须单列理由：① `docs/ui-demo/demo.html` 是 `docs/ui-demo/package-demo.py` **打包生成**的单文件应用、`dist/**` 才是源（`AGENTS.md` 现行阶段产物即它）⇒ 整个 `docs/ui-demo/**` 按产品交付物对待；② `docs/requirements.md`／`docs/product-requirements.md`／`docs/implementation-requirements.md`／`docs/development-plan.md`／`docs/features/**` 被 `tools/validate_development_docs.py` 直接读取且决定范围与正式依赖；③ `docs/research/**` 由 `tools/verify-research-records.mjs` 校验，与 `contract-status.json` 同为台账。依据 §3「不能只因文件位于 `docs/` 就视作纯文档」。

不在正面清单内的路径一律 B 档：`.github/**`、`tools/**`、`packages/contracts/openapi.json`、真实迁移目录 `services/api/db/migrations/**`（注意：仓内**不存在** `db/migrations/`）、任何产品行为代码（`services/**`、`apps/**`、`packages/**` 中非 `tests/**` 的部分）。

判定以**合并时的最终 diff** 为准：包括 rebase、解冲突以及之后的追加提交，不只看首次提交的清单。

**升档**：一旦触及排除项，当场升 B 档；升档由发现者宣布并写进 PR 评论，旧审查记录随之作废，按 B 档重新批复。

### 10.2 独立审查不因分层而取消（硬约束）

- 审查者身份：**审查者 ∉ {实现者, 推送者, 派发者}**。只写「审查者 ≠ 实现者」不够——本仓常态是写手实现、指挥推送并建 PR，那样指挥自任审查者字面合规但零独立性。
- 审查记录载体：审查者应在该 PR 上留下 `COMMENT`（或 `APPROVED`），正文含 reviewed SHA 与逐条结论；口头或离线结论不算，合并注记也不能替代审查本身。
- **审查者无账号时的「代贴」**（2026-10-26 用户批准）：子代理等没有 GitHub 身份的审查者，允许由指挥**代贴**其原始结论，但必须同时满足——① 正文首行写明「审查者：<主体标识>（本评论由指挥代贴）」并声明审查者 ∉ {实现者, 推送者, 派发者}；② 结论方向与全部阻塞项**逐字保留**，指挥不得改写、删减，也不得以自己的判断替换审查者的判断；③ 审查者实际跑了什么／没跑什么、负控制结果一并贴出；④ 合并注记链接该代贴评论，且 §10.4 交接清单里写明「代贴」这一事实。审查者若本就是指挥本人（自己实现），仍只能走 B 档——上一条不变。
- 指挥不得对自己实现的 PR 行使「审查通过」。若唯一可用的审查者就是本人，该 PR 只能按 B 档交监工。
- 四项必查：① **档位**——逐文件核对，以 GitHub 侧最终 diff 为准（本地 `origin/main` 可能陈旧，实测出现过本地报 12 个文件、实际只 1 个）；② **负控制**——仅当 PR 新增或修改了行为断言时适用，纯文档 PR 不适用（与 §3「不默认要求变异／负控制」一致）；③ 是否放宽既有断言；④ 是否改动计数钉、末项钉、`tools/doc-anchors-baseline.json` 或治理台账。
- **§7 合并门禁的全部条目对 A 档同样适用**（重读当前 HEAD、base、非草稿、冲突、reviews、未解决线程）。§10 是在 §3、§7 之上**加限制**，不是替代；`docs/**` 的「适用 CI」可能为空，但这不降低 §7 的要求。
- CI 绿不替代独立审查；独立审查通过也不替代 CI。

### 10.3 合并留痕

合并者在 PR 上留一条注记，至少包含：审查者账号、reviewed SHA、CI 项数与结论、合并者、合并方式（squash）、未关闭的 issue、未部署。注记里必须**链接审查者本人的 COMMENT／APPROVED**，避免变成合并者自证。审查评论不因合并删除。

### 10.4 交接清单

1. 哪些 PR 是 A 档自合并（审查者账号＋reviewed SHA＋审查评论链接），哪些走了监工批复；
2. 档边界就是 §10.1 的正面清单＋排除清单；
3. 治理类文档（含本文件）、`.github/**`、迁移类改动**永远**属于 B 档，与「改动小」无关；
4. 与 §1／`AGENTS.md` 的关系：A 档按本条例外执行，B 档不变；两者冲突时以本条对 A 档的规定为准，并由发现者当轮把冲突记入交接；
5. 升档由发现者宣布，旧审查作废并按 B 档重批。
