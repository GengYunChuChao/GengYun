## 6 风险与需裁定项

1. **同分判定用严格相等（`===`）**：只把「分数完全相同」判为并列，浮点近似同分（如 0.820 vs 0.819）仍按唯一 Top1 处理。这是**刻意**的保守选择——不引入阈值猜测、不改写分数。若要求「近似同分也算并列」，需先定阈值口径（属契约/算法变更，本片不做）。
2. **`conflict_fields` 新增 `source.*` token**：契约对 `conflict_fields` 只约束元素为字符串与条数上限，故未改契约；但这属**语义扩展**——若有下游按标签字段名穷举，会见到 `source.validity` / `source.review_status`。本片已在小程序侧给人话标签并对未知 token 原样透传。**需裁定**：是否要在契约或 `contract-implementation-status` 层显式登记这两个 token。
3. **`unverified` 不拦（有意）**：生产替身来源 `review_status` 恒为 `unverified`（`services/api/src/ocr/reference.ts:46`），若要求「未核对即不得 `matched`」，替身演示路径会整体变 `conflict`。本片按「只拦明示失效/被拒」处理，替身路径的用量放行仍由 `DoseSource` const 约束 + `gateDoseCards()` 单独把关（`tests/unit/ocr-service.test.mjs:435` 等）。**需裁定**：产品口径是否要求 `unverified` 也降级。
