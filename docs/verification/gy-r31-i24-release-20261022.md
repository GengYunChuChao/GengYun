## 3. 备份恢复演练读数（2026-10-22 真跑，本地 PG 17.11，端口 55728）

**为什么要做**：空缺 G5 —— 既有演练只证明「dump 可读」，没有证明「库没了能重建」。本次把**源库真删掉**
再恢复，才算把 §7.4「数据库回滚」的可行性坐实到本机等价路径上。

- 服务拉起方式：`Invoke-CimMethod -ClassName Win32_Process -MethodName Create`（⛔ 未用 `Start-Process`），
  `postgres.exe -D <datadir> -p 55728`；`initdb` 同法。演练目录在仓外：
  `E:\GengYunCommander\.pg17\tmp\r31-i24-drill\`，演练后已停库。
- 备份脚本：仓库既有 `deploy/postgres-cvm/backup-postgres.sh`（**未修改**）。

| 迁移版本 | `0001..0027`（27 个）；第二次 `up` 输出「已应用：（无）」⇒ 幂等通过 |
| 基本表 / 视图 | **74 / 8** |

### 3.2 删库 → 恢复全链路

| 阶段 | 命令 | 读数 |
| --- | --- | --- |
| ① 删库前快照 | `psql -tAc "…count(*)"` | `users=2 media=1 jobs=1 tables=74 views=8 ledger=27` |
| ② **真删库** | `dropdb -h 127.0.0.1 -p 55728 -U gengyun_cvm_owner gengyun` | `DROP_EXIT=0`；`pg_database` 中 `gengyun` 计数 **0**；再连报 `FATAL:  database "gengyun" does not exist`（exit 2） |
| ③ 重建空库 | `createdb -O gengyun_cvm_owner -T template0 -E UTF8 gengyun` | `CREATEDB_EXIT=0` |
| ④ 从 dump 恢复 | `pg_restore --exit-on-error --no-password` | `RESTORE_EXIT=0`；恢复日志 **0 字节**；致命行 **0** |
| ⑤ 恢复后快照 | 同 ① 的 SQL | `users=2 media=1 jobs=1 tables=74 views=8 ledger=27` ⇒ **与 ① 逐位一致** |
