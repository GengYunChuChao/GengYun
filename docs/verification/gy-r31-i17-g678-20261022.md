## 1. G6：角标更新失败被静默清空

### 1.1 缺口

未读数取不到时（网络／服务未接线／权限），原实现把角标写成空串：

- 空串在 `unreadText` 口径里就是「0 条未读」的展示形态（`unreadText(0) === ''`）；
- 于是**读取失败**被渲染成**「你没有未读」**，用户看不出角标是旧的还是真的清零了；
- 失败也没有任何可检索痕迹（没有日志、没有告警）。

### 1.5 为什么这样断言

- **锁「不清空」而不是锁某个字符串**：A1/A2 断的是「失败前后角标**相等**且不等于 `''`/`'0'`」。
  换成「保留上一次已知值」「明确不更新」两种实现都能过，只有「静默清空」过不了——这正是缺口本身。
- **A2 同时盯页面与 Tab**：两处 catch 是**两条独立代码路径**（页面 `_applyUnread` 会顺带写 Tab，
  Tab 又有自己的 `pageLifetimes.show` 自读）。只测一处，另一处照样能静默清空。
- **A3 单列「从未读到过」**：这是「保留上一次已知值」最容易退化成「干脆写 0」的边角——没有上一次时
  唯一正确的展示就是继续不显示数字。
- **键集断言用 `sort()` 后 `deepEqual(['code','event'])`**：比只数键个数更严——键名变了也会红，
  且比逐字段断言更能挡住「顺手塞一个 `message`/`token` 进去」。
- **A2 再叠一条正则**：`synthetic-token|synthetic-code|\+?\d{11}` 是「日志不许泄密」这条要求的可执行形态；
  只断言键集是挡不住「把令牌拼进 `code`」的。
- **A1 是「换断言的对象」，不是删断言**：旧断言把「失败即清空」固化成契约（`assert.equal(…, '')`），
  与缺口要求直接冲突。修法是把断言对象从「清空」换成「保留 + 留痕」，覆盖面不减反增
  （多了告警与键集）。这与 `#459` 分支上 `14a49986` 的处置方式一致。

### 2.5 为什么这样断言

- **为什么用性质断言**：G7 的缺陷是**语义不实**，不是某个字符串写错。锁死新文案会让下一轮文案评审必红，

- **B3 只数「标记行」**：`wxml` 里源码注释也有「有生产路径」字样（`:143`），把注释算进计数会把
  「注释口径」和「用户可见文案」混在一起；先用 `replace(/<!--[\s\S]*?-->/g, '')` 去掉注释再计数，
  这条断言才是在说「用户看到的东西」。
- **B2 把断言钉在服务端事实上**：页面说「三类有生产路径」，依据必须是 `events.ts` 的映射真的存在；
  否则文案和实现会一起漂。
- **B5 是「文案 ↔ 能力」的一致性检查**：`#448` 之后消息行真的能跳，若哪天文案回退成「不提供跳转」，
  这段话就又变成假话；同时用 `bindtap="onOpenTarget"` 反向确认「说的能力确实存在」。

```
//     跳转入口与目标类型判据在页面侧（`pages/messages`），本模块**不**拼路由、不伪造目标标题；
//   - 首版**不接**微信外部推送；`comment`／`like` 两类消息自 `#422` 起已有生产路径
//     （社区事件经消息域端口真落库），本模块仍不为其造任何替身消息。
```

### 3.4 本片新增断言（`tests/unit/miniprogram-ui-auth-integration.test.mjs:768`，性质断言）

| # | 断言（每条一句） |
| --- | --- |
| C1 | 头部注释（截到 `const auth = require('./auth')` 为止）不得包含「目标可用性端口未接线」「`reference_state` 恒为」「暂无生产路径」三条旧说法。 |
| C2 | 头部必须出现事实锚 `#425` 与 `#422`（两片接线都要有出处，不能只说「已接线」）。 |
| C3 | 「其余 N 型恒为 `unavailable`」的 N 必须等于 `TARGET_REF_TYPES` 长度减 2（16 − 2 = 14）——闭集扩容时这条会红，避免注释里手写常量悄悄过期。 |
| C4 | 头部必须含「不泄露」口径（与 `reference-community.ts`「不存在／未发布／下架／无权同形」同一句事实）。 |

### 3.5 为什么这样断言

- **C1 锁旧说法，不锁新说法**：注释可以有多种正确写法，但「端口未接线」在 `#425` 之后一定是错的。
- **C3 用闭集长度推导而非写死 14**：这正是这类注释过期的最常见方式——闭集加了类型，注释里的数字没人改。
  推导式断言会在**闭集变更的那一刻**红，而不是等用户发现注释和实现不一致。
- **C4 是安全口径**：`reference_state` 不能变成「存在性探针」，注释里必须保留这条约束，
  否则下一个改实现的人会以为「反正只有 unavailable，随便答」。

## 6. `messages` 页剩余最小缺口（只列不改）

1. `miniprogram/pages/messages/messages.wxml:76` 空态 desc 仍写「审核结果产生后会出现这里。」——`#422` 之后评论／点赞也会产生消息，这句仍是单类型旧口径（G7 同类遗漏，不在本片两处行号范围内）。
