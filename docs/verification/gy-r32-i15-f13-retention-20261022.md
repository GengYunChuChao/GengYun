## 2. 三类读数（保留 / 隐藏 / blocked）

`CommunityOwnerPurgeCounts`（`community/store.ts:180`）现在分五项：

| 字段 | 含义 | 是否计入“已完成” |
| --- | --- | --- |
| `retained` | 正文原样保留的帖子+评论（含仅移除媒体的行） | 是（保留结果，不是写操作） |
| `redacted` | 正文因清除个人信息被改写 ⇒ 旧审核摘要失效 ⇒ 待重审（行仍在库） | 是（脱敏完成；公开状态交回审核口径） |
| `hiddenMedia` | 被移除的媒体引用条数 | 是（隐藏完成） |
| `records` | **真实改动/删除**的行数（脱敏帖评 + 仅移媒体帖评 + 清 detail 举报 + 物理删点赞） | 不是“保留”的替代 |
| `blocked` | 未完成的处理项数（见 §4） | **否** ⇒ 回执 `online_state='blocked'` |

证据串（`privacy/user-data-deletion.ts::makeHandler`）形如：
`community:online-purged:<records>;community:idempotency-purged:<n>;community:retained:<n>;community:redacted:<n>;community:media-hidden:<n>;community:blocked:<n>;community:blocked-reasons:<codes>`。

## 4. blocked 的真实来源（为什么不报 completed）

`community/purge.ts` 的端口在“有保留/脱敏内容”时把下列事实计入 `blocked`（`blocked=1`，
原因逐条写进 `blockedReasons`）：

1. `author-row-reference-not-replaced`：行级 `community_posts.author_id` / `community_comments.author_id`
   仍是**原账户 id**。两列都是 `uuid NOT NULL REFERENCES users (id) ON DELETE CASCADE`（迁移 `0022`），
   且运行时角色对两表的 `UPDATE` **列级授权不含 `author_id`**
   （`deploy/postgres-cvm/sql/20-login-roles.sql` 的社区段）；本片**不新增迁移、不改授权**
   ⇒ 无法把行级作者改成随机引用。投影层已换成随机注销引用，但这不等于 F13 的
   “内部作者换注销引用、删除账号映射”全部完成。
   ⚠️ 连带风险：身份域若将来物理删除 `users` 行，`ON DELETE CASCADE` 会级联删掉本应保留的帖子/评论
   ——本片不改迁移，作为**阻塞项**登记（需要单独的 schema/授权切片）。
2. `author-reference-not-durable`：注销引用只存在进程内（阶段 1 本地假名投影），
   重启即丢；`public_authors`/`author_links` 未接线、本片不新增迁移。
3. `author-reference-unavailable` / `author-reference-failed`：注入的作者目录没有 `anonymize` 能力，
   或调用失败（测试 `c2` 覆盖“存储失败 ⇒ blocked + HANDLER_FAILED”）。

因此：**有社区保留内容的主体，回执社区模块就是 `blocked`**（`error_code=POLICY_BLOCKED`），
`completionStatus().completed=false`。没有社区内容的主体不受影响（`blocked=0`，如实 `completed`）。

## 5. 未取得项（如实登记，不计入通过）

1. **真 PG17 集成臂未取得**：`node tests/integration/community-pg.mjs` ⇒
   `SKIP real PG17: COMMUNITY_PG_TEST_URL 未设置 … EXITCODE=77`（本机无 PG17 二进制/服务）。
   该脚本 §10c 已按新口径改写（保留/脱敏/媒体/blocked 读数），须在 CI 首次运行确认。
   本机取得的最接近证据是 §3.2 的 PGlite（内嵌 PG）装配臂：同一条 `purgeOwnerData` SQL 真执行。
2. **行级 `author_id` 替换 + 注销引用持久化**：见 §4 第 1/2 条（阻塞，需迁移/授权/作者域接线）。
3. **“媒体已可靠脱敏”的判据**：社区存储没有媒体去标识证据面 ⇒ 本片按“全部媒体均不能可靠脱敏”
   移除引用；若后续接媒体域，应改为逐媒体判定，而不是继续全量移除。
4. **正文个人信息清除只覆盖确定性模式**（手机/座机/邮箱/身份证/IM 标注/门牌），
   不声称覆盖所有形态；未识别形态仍可能留在正文里。
5. **`region_code` 保留**：它是 6 位县级行政区划（非精确坐标/门牌），按 F13“精确位置”口径不清除；
   如产品口径要求连县级也清，需要单独裁定。
6. **回执 state**：有社区内容的注销请求整体为 `blocked`（因 §4），这是**如实状态**，
   不是本片引入的失败；不得为了“看起来完成”把 blocked 改回 completed。
