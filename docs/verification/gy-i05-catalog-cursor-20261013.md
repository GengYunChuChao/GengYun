## 缺陷与结果

原 `profile/service.ts:list` 在每一页签发 `Date.now()+15分钟`，第二页可将整条链继续延长；游标绑定 user/kind/filter/watermark/sort，但未绑定 auth_epoch。
本次提取目录分页组件，整条链保留第一游标的截止。第 14 分钟翻页后，第 15 分钟减 1 毫秒仍可读取，到整点必须 400 INVALID_CURSOR；当前会话仍有效但账号版本已变化时，旧游标同样失效，首页重取可恢复。

游标加入版本、auth_epoch 与 `profile-catalog/v1` 签名域，校验字段闭集、规范 base64url、HMAC、当前目录中的 after 键、绑定及期限。用户／目录种类／父级过滤器／稳定目录键排序／全量新鲜目录水位保持绑定，limit 仍允许 1..50 变化且不会续期。签名配置缺失明确失败。

服务继续在原数据库事务中重验账号、会话和最新目录，锁／权限／目录配置比对不变；没有静态目录冒充数据库成功。接口、items/next_cursor 封套、默认 limit=20、稳定目录键顺序和 no-store 成功响应不变。
资料和授权分页组件未改。机器／中文对照仅同步本次收短的目录调用证据行，状态不升级；#117 的其他文档修订没有混入本 PR。

## 兼容、消费者与回滚

升级前签发的旧格式游标返回 400 INVALID_CURSOR；没有伪造迁移或兼容续期，客户端重新请求不带 cursor 的首页即可。目录键与数据没有迁移，无服务端表结构变更。
现有小程序实际 JS 在 Node VM 中验证：中途游标失效时不发布已累积的半份目录、不开放编辑／保存、不清登录、不自动循环重试；用户点重新读取从无 cursor 的首页开始，完成全部页后恢复。生产页面代码未改；Node VM 不等于微信工具编译或 Android 真机验收。

代码回滚会恢复旧游标实现及滑动／epoch 缺口；新游标在旧实现中也会失效，需重取首页。回滚没有数据库 down 或存量记录写入，不应以回滚作为通过安全修复验收。
