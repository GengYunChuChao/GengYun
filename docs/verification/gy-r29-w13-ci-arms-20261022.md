## ① 假绿漏洞复核（先判事实）

### 1.1 守卫侧：硬编码一个键，对所有自起集群脚本生效

`origin/main`（`a2ab0d9`）的 `tests/unit/ci-real-pg-wiring.test.mjs`：

- `:228-238` `const SELF_CLUSTERED_ENV = Object.freeze([...])`，其中 `:235` 是
  `key: 'GY_I19_PG_ROOT',` ——**一个键，全体自起集群脚本共用**；
- `:557` `for (const { key, pattern, hint } of SELF_CLUSTERED_ENV) {` —— 对**每个** `SELF_CLUSTERED_SCRIPTS` 成员都按这个键核对 step 的 `env:`。

### 1.2 脚本侧：`messages-purge-pg.mjs` 读的是另一个键

`tests/integration/messages-purge-pg.mjs`：

- `:92` `const rootDir = process.env.GY_W11_PG_ROOT ?? tmpdir();` ——**它读 `GY_W11_PG_ROOT`**；

- `:63-66` 只有 `GY_PG_BIN` 缺失时打印 `SKIP` 并 `exit 77`；**数据根键缺失没有 77 分支**，直接 `?? tmpdir()` 回落。

## ② 修法与映射表

### 2.1 机制

`tests/unit/ci-real-pg-wiring.test.mjs`（本片改动）：

- **删除** `SELF_CLUSTERED_ENV`（键对全体硬编码）；
- **新增** `SELF_CLUSTERED_ROOT_KEY`（`:256-260`）——**脚本 → 它自己读的键**：

| 脚本 | 它真正读的数据根键 | 源码真值 |
| --- | --- | --- |
| `tests/integration/backup-purge-pg.mjs` | `GY_I19_PG_ROOT` | `:89` |
| `tests/integration/backup-copies-purge-pg.mjs` | `GY_I19_PG_ROOT` | `:97` |
| `tests/integration/messages-purge-pg.mjs` | **`GY_W11_PG_ROOT`** | `:92` |

- `SELF_CLUSTERED_ROOT_KEY_PATTERN = /^GY_[A-Z0-9_]*_PG_ROOT$/`（`:263`）：认「根键」的形状，也是「装饰性 env」的识别口径；
- `rootKeyOf({script, scriptSource, declaredRootKeys})`（`:604`）、`selfClusteredEnvOf(...)`（`:613`）、`selfClusteredProblems(...)`（`:636`）三个函数按映射表产出「该给的键/该有的值形状」；
- `declaredRootKeys` 可注入（默认 `SELF_CLUSTERED_ROOT_KEY`）——**只为负控制**能不动冻结常量地变异映射。

### 2.2 四条判据（防再次假绿）

1. 登记表**必须**有该脚本（漏登记 ⇒ 红）；
2. 登记键**必须等于脚本源码真值**——`detectedRootKeys()` 从源码扫 `process.env.GY_*_PG_ROOT`，两边不一致 ⇒ 红；
3. step **必须**给出该键，且值必须是 `${{ runner.temp }}...` 形状（⛔ 不落仓库/系统目录）；
4. step 里出现该脚本**不读**的其它 `GY_*_PG_ROOT` ⇒ 红（点名「装饰性 env」）。

第 2 条是关键：只做「按脚本映射」而不和源码核对，**把映射写错**本身就变成新的假绿通道（错的键会让判据 3 去核对错的 env，从而放行装饰性 env）。第 4 条挡住「两个键都给，总有一个对」的蒙混。

红灯与报错原文（4 个用例红：前向⑥、反向控制⑧⑨⑩）：

```
✖ 前向⑥（判据⑦＋⑧）：每个受管脚本所在 step 先 CREATE DATABASE 再 node，且库名与该 step 传入的一致
✖ 反向控制⑧：判据⑥⑦⑧⑨ 各自的变异都必须红，且消息能定位到脚本/库名
```
