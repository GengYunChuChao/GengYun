## 0. 结论（可判真假）

> 仓内会参与 diff 的文本文件，CR 字节已归零：守卫单测按**扩展名**扫全仓 9 类文本（已声明的 `.md/.mjs/.ts/.json/.yml` ＋ 同类但未声明的 `.sql/.js/.py/.cjs`），共 **1340 个文件、CR 合计 0**（`tests/unit/eol-normalization.test.mjs` 断言；负控制在仓库里注入 1 个 CRLF md ⇒ exit 1，删掉后复绿）。规范化提交**除行尾外零差异**——`git diff --ignore-cr-at-eol --stat` 空输出，且 8 个文件逐个按 blob 比对「旧 blob 丢掉 CRLF 后与新 blob 逐字节相等」。门禁不再自己制造抖动：`node tools/verify-contract-status.mjs --write-doc` 现在是**幂等**的（sha256 前后相同、CR=0、`git status --porcelain` 无输出）——`#469` 那条「跑一次门禁就翻回 LF、再产生 200 行全红 diff」的回路被切断。

## 1. 谁含 CR（改前逐字节实测）

口径：`node` 读 `Buffer` 逐字节数 `0x0D`，**不解码成字符串、不 `Get-Content` 往返**（按行读再拼回去，CR 早被吃掉，永远判绿）。`CRLF` = CR 后紧跟 LF；`孤立 CR` = 其余（两种都会污染 diff，都算违规）。

| 文件 | CR（总数） | CRLF 行 | 仅 LF 行 | 孤立 CR | 说明 |
| --- | --- | --- | --- | --- | --- |
| `docs/verification/gy-i04-login-chain-20261021.md` | 407 | 407 | 0 | 0 | 整份 CRLF |
| `docs/architecture/contract-implementation-status.md` | 200 | 200 | 0 | 0 | 整份 CRLF，`#469` 的副作用本体 |
| `docs/pr-review-policy.md` | 152 | 152 | 0 | 0 | 整份 CRLF |
| `README.md` | 243 | 243 | 29 | 0 | **混行尾**（`git ls-files --eol` = `i/mixed`） |
| `AGENTS.md` | 45 | 45 | 0 | 0 | 整份 CRLF |
| `docs/verification/gy-r31-i17-g5-20261022.md` | 1 | 1 | 338 | 0 | 只有末行是 CRLF，其余 338 行本就 LF |
| `services/api/src/routes/community.ts` | 1 | 1 | 406 | 0 | 非 md，混行尾，被 `*.ts` 规则覆盖 |
| `tests/unit/gy-i22-message-parity.test.mjs` | 743 | 743 | 0 | 0 | 非 md，整份 CRLF，被 `*.mjs` 规则覆盖 |

按派单口径清单：

- **派单点名面**（`docs/architecture/*.md` ＋ `docs/verification/*.md`，共 238 个 md）：**含 CR 的 3 个**，最大的三个依次 `gy-i04-login-chain-20261021.md`（407）、`contract-implementation-status.md`（200）、`gy-r31-i17-g5-20261022.md`（1）。
- **守卫扫描面**（**改前口径**：`docs/**/*.md`，297 个 md；2026-10-22 扩面后的口径见 §4.5）：**含 CR 的 4 个**（多出 `docs/pr-review-policy.md`＝152，它在这个面里排第三，把 1 个 CR 的 g5 挤到第四）。
- **全仓 md**（再加 `README.md` 243、`AGENTS.md` 45）：**6 个**。
- 再加 2 个非 md 文本，**合计 8 个文件、1792 个 CR 字节**，全部是 CRLF，孤立 CR = 0。
- 对照组（**故意不动**）：`docs/verification/assets/` 下的 `.log`/`.cjs`/`.mjs` 与 148 个 png/jpg 仍含 CR 字节——那是证据快照，必须原样存取（§2.2）。

## 2. 根因：三件事叠在一起才不自愈

### 2.1 `#469` 把台账整份写成 CRLF

main 侧 0 个 CR / 200 行 LF，`#469` 侧 200 CR / 200 行。`#469` 之后每张动该台账的 PR 都会与它产生「全文 1 块」的假冲突，review 里看不到真实改动的行。

### 2.2 仓库没有根 `.gitattributes`，生效的 `core.autocrlf=false`

**生效值实测**（2026-10-22，`git config --get --show-scope --show-origin core.autocrlf`，只回一行＝生效值）：

```text
local	file:E:/GengYunCommander/GengYun_Agent2/.git/config	false
```

逐作用域（`git config --list --show-origin --show-scope | Select-String autocrlf`）：

```text
system	file:D:/Git/etc/gitconfig	core.autocrlf=true
local	file:E:/GengYunCommander/GengYun_Agent2/.git/config	core.autocrlf=false
```

⇒ 仓库级 `false` **覆盖**机器级 `true`，**本仓库生效值是 `false`**（此前若被读成 `true`，以本节读数为准；推理方向不变：正因为生效值不是 `input`/`true`，CRLF 一旦入库就停在库里，检出不做事后归一化）。

翻过去就停在那里，没有任何机制把它翻回来。但仓库**不是完全没有**属性声明：`docs/verification/assets/` 下两个子目录各自带一份 `.gitattributes`：

```text
* -text whitespace=cr-at-eol
```

路径：`docs/verification/assets/i07-wechat-main8932ba5-pr80b5a6468/.gitattributes`、`docs/verification/assets/local-knowledge-native-20261011/.gitattributes`。更深的属性优先 ⇒ 这两处证据快照被钉成**原样存取**，根规则管不到它们。这也是根 `.gitattributes` **不能写 `text=auto`** 的现实理由：`docs/verification/assets/` 下有 148 个 png/jpg 与 `.log`/`.cjs` 证据快照，让 git 自动探测二进制，猜错一次就把资源文件写坏。实测这两个目录下 `.md` = 0 个，所以「`docs/**/*.md` 零 CR」与「证据快照字节不动」两条不打架。

### 2.3 门禁按 LF 重写，把文件在两种状态间来回推

`tools/verify-contract-status.mjs:412`：`writeFileSync(DOCUMENT_FILE, expected)`，而 `expected` 是 `\n` 拼出来的字符串 ⇒ 谁跑一次 `--write-doc`，谁就把 200 行 CRLF 翻回 200 行 LF，再产生一次全红 diff。**这条回路是本片要切断的东西**：在本分支上它已闭合（§5）。

## 3. `.gitattributes`（新增，全文）

```text
# 行尾铁律：文本文件一律 LF（2026-10-22，收口 #469 的副作用）。
#
# 背景：`#469` 合入 main 时把 `docs/architecture/contract-implementation-status.md` 整份从 LF
# 翻成 CRLF（main 侧 0 个 CR、`#469` 侧 200 CR / 200 行），仓库当时没有 `.gitattributes`，
# 而本机**生效**的 `core.autocrlf` 是 `false`（仓库级 `.git/config` 的 false 覆盖机器级
# `D:/Git/etc/gitconfig` 的 true；`git config --get core.autocrlf` ⇒ `false`）⇒ 不会自愈。
# 后果是每一张动该台账的 PR 都跟它产生「全文 1 块」的假冲突，
# 而 `node tools/verify-contract-status.mjs --write-doc` 按 LF 重写 ⇒ 谁跑一次门禁谁又翻回去，
# 再产生一次 200 行全红 diff。这里用**声明式**规则把「检出 = 提交 = LF」钉死，不再靠人肉自觉。
#
# 只写 `eol=lf`，**不写** `text=auto`：
#   `text=auto` 让 git 自己猜二进制，猜错一次就把资源文件写坏（本仓 `docs/verification/assets/`
#   下有 148 个 png/jpg、以及 .log/.cjs/.mjs 证据快照）。显式列举扩展名比自动探测安全。
#   未列出的路径（图片、`.log`、`.cjs` 等）保持 git 默认行为：原样存取，不做任何行尾转换。
#
# ⚠ 声明面 ≠ 全仓（2026-10-22 补注）：本文件只钉下面 5 类扩展名，**不是**「全仓强制 LF」。
#   `.sql` / `.js` / `.cjs` / `.py` / `.wxml` / `.wxss` / `.sh` / `.ps1` 等一律**未声明**
#   ⇒ git 原样存取、不转换（正因为没有 `text=auto`）。要扩面就在下面加一行，并连带想清楚
#   `git add --renormalize` 的后果；守卫单测 `tests/unit/eol-normalization.test.mjs` 扫得比这里宽
#   （按扩展名扫全仓 9 类文本），那是「早发现漂移」，不代表这些类型已经被强制 LF。
#
# ⚠ 证据快照的优先级（2026-10-22 补注）：`docs/verification/assets/` 下有两个子目录
#   （`i07-wechat-main8932ba5-pr80b5a6468/`、`local-knowledge-native-20261011/`）各自带一份
#   `.gitattributes`（`* -text whitespace=cr-at-eol`）。git 属性**更深目录优先**，所以那里的
#   `.cjs` / `.mjs` / `.log` 不会被下面的 `*.mjs` 规则转换 —— 实测 `git check-attr` 得
#   `text: unset`。这两份文件一旦被删，根规则就会重新匹配：`executed-service.mjs`（1 个 CR）
#   会被静默转换（实测 hash `6ce91fd9` → `7df7c72d`，见证据页 §4.7）；`.log` / `.cjs` 不匹配
#   任何根规则。图片没有任何声明（`text/eol: unspecified`），不受本文件影响。
#   守卫单测最后一条把这两份 `.gitattributes` 的存在与 `-text` 一起钉住。

# 文档与台账
*.md     text eol=lf

# 脚本 / 工具
*.mjs    text eol=lf

# 源码
*.ts     text eol=lf

# 配置与清单
*.json   text eol=lf
*.yml    text eol=lf
```

生效验证（`git ls-files --eol`，逐文件）：8 个被规范化的文件都变成 `i/lf w/lf attr/text eol=lf`；`.gitattributes` 自身 `attr/`（未声明，按 git 默认）。属性声明本身也被守卫单测钉住（§4.5 最后一条用例）：五类扩展名必须在位、且全文不许出现 `text=auto`。文件末尾两段 `⚠` 补注是 2026-10-22 收口时加的：一段讲**声明面 ≠ 全仓**（§4.6），一段把**证据快照的优先级依赖**写明（§4.7）。

## 4. 规范化：只动行尾的证明

### 4.1 写入时的不变量（脚本自检，不满足就不落盘）

对 8 个文件逐个：

1. 先扫一遍，**孤立 CR 必须为 0**（本例全部为 0；若不为 0 直接抛错，不猜「它想干什么」）；
2. 只在 `0x0D 0x0A` 处删除 `0x0D`，其余字节**按原顺序、原数量**写出；
3. `旧内容.replace(/\r\n/g, "\n")` 与新字节**逐字节相等**（文字、顺序、空行零改动）；
4. 字节减少量 `== CRLF 个数`（本例 1792）。

### 4.2 命令原文：除行尾外零差异

```text
$ git diff --ignore-cr-at-eol --stat bd7f2ea3^ bd7f2ea3 -- AGENTS.md README.md docs/architecture/contract-implementation-status.md docs/pr-review-policy.md docs/verification/gy-i04-login-chain-20261021.md docs/verification/gy-r31-i17-g5-20261022.md services/api/src/routes/community.ts tests/unit/gy-i22-message-parity.test.mjs
（无输出）
```

> 取证当时该命令写作 `HEAD^ HEAD`（那时 `HEAD` 就是 `bd7f2ea3`）；这里钉成固定 SHA，免得后继提交（第二个提交只加两个文件）让区间漂走、把「空输出」变成一句无从复核的话。

### 4.5 守卫单测 `tests/unit/eol-normalization.test.mjs`

扫描面（2026-10-22 扩面后，全部导出）：按**扩展名**扫全仓 `SCAN_EXTS = ['.md', '.mjs', '.ts', '.json', '.yml', '.sql', '.js', '.cjs', '.py']`；整目录跳过 `SCAN_SKIP_DIRS = ['.git', 'node_modules']`；显式排除 `SCAN_EXCLUDE_PREFIXES = ['docs/verification/assets/']`（证据快照被 `-text` 钉成原样存取，里面的 `.log`/`.cjs`/`.mjs` 本来就含 CR，靠「碰巧没扫到」是不行的）。判定读**字节**，不做字符串往返。

导出的判定函数（供负控制与后续守卫复用，同一套判据，不另立一套）：

- `countLineEndings(buffer)` → `{ cr, crlf, loneCr, lf, bytes }`

- `collectScopeFiles({ root, exts, skipDirs, exclude })`、`SCAN_EXTS`、`SCAN_SKIP_DIRS`、`SCAN_EXCLUDE_PREFIXES`、`ROOT`

### 4.6 声明面 ≠ 归一化面（避免把本页读成「全仓强制 LF」）

`.gitattributes` 只声明 **5 类**扩展名 ⇒ 只有它们是 git **真的会转换**的面（检出/提交时按 LF 归一化）。守卫扫 **9 类**，多出的 `.sql/.js/.cjs/.py` 是**同类文本但未声明**：

- 未声明类型**不会被 git 转换**：根 `.gitattributes` 没有 `text=auto`，未匹配任何规则的路径走 git 默认行为（原样存取）。所以现存的 `.sql/.js/.cjs/.py` 即使带 CRLF，也不会被「悄悄修好」——守卫扫它们只是为了在**有人新引入 CR** 时变红（早期告警），**不代表这些类型已被强制 LF**。
- 反过来也有一条边界：`.wxml` / `.wxss` / `.sh` / `.ps1` / `.html` / `.vue` / `.log` 连扫描面都不在（不在本片范围；要扩就改 `SCAN_EXTS` 一行）。
- 要真正扩面到 `.sql/.js/.cjs/.py`，得在 `.gitattributes` 加规则 **并** 跑一次 `git add --renormalize`（会产生成块 diff），那是另一片的事；本片只把「扫得宽、改得窄」这件事写明，不偷偷放宽声明。
- 排除面也不是全场豁免：`docs/verification/assets/` 下被排除的是 **32 个**文件（28 个 `.json` ＋ 3 个 `.cjs` ＋ 1 个 `.mjs`）；该目录下的 `.md` = 0 个，所以「全仓 `.md` 零 CR」与「证据快照字节不动」两条不打架。

### 4.7 证据快照的优先级：不靠「碰巧」，靠更深一层的 `-text`（实测）

根规则 `*.mjs text eol=lf` 会匹配到 `docs/verification/assets/i07-…/executed-service.mjs`，而它**必须**原样存取（含 1 个 CR，是字节级证据）。真正压住转换的是子目录里那份 `* -text`（git 属性**更深目录优先**）。三条实测：

```text
# 1) 属性解析：图片无任何规则；快照被 -text 钉住
$ git check-attr -a -- docs/verification/assets/gui-adaptive-250c4d4/12-tool-basic-info.png
（无输出 ⇒ text/eol 均 unspecified）

$ git check-attr -a -- docs/verification/assets/i07-wechat-main8932ba5-pr80b5a6468/merged-tests.log
…/merged-tests.log: text: unset
…/merged-tests.log: whitespace: cr-at-eol

$ git check-attr -a -- docs/verification/assets/i07-wechat-main8932ba5-pr80b5a6468/executed-service.mjs
…/executed-service.mjs: text: unset
…/executed-service.mjs: eol: lf          # 根规则匹配到 eol，但 text=unset ⇒ 不做转换
…/executed-service.mjs: whitespace: cr-at-eol
```

```text
# 2) 反事实：同一份字节（6701 bytes，1 个 CR），只改 --path 让属性解析走不同规则
$ git hash-object --no-filters -- <快照路径>                          6ce91fd9ea6ad47e531064f1ac3b2f9e5b50a5ea
$ git hash-object --path=<快照的真实路径> -- <快照路径>                6ce91fd9ea6ad47e531064f1ac3b2f9e5b50a5ea   ← 与 HEAD blob 相同
$ git hash-object --path=tools/probe-counterfactual.mjs -- <快照路径>  7df7c72d42548e2acc202aaa5abd7e0e6ea043d5   ← 走根 *.mjs 就会被转换
```

```text
# 3) 临时 CRLF 文件（仓外，仅探针）：声明路径 vs 快照路径
$ git hash-object --no-filters -- $env:TEMP/gy-eol-probe.md                              3ff8b80ecba1895c00fa31b1ab7150a22a047369
$ git hash-object --path=README.md -- $env:TEMP/gy-eol-probe.md                          b9b32e519fe8a8d8239507d9015220a48dcc13fc   ← 命中 *.md ⇒ 转换
$ git hash-object --path=docs/verification/assets/local-knowledge-native-20261011/probe.md -- $env:TEMP/gy-eol-probe.md
                                                                                        3ff8b80ecba1895c00fa31b1ab7150a22a047369   ← 命中 -text ⇒ 不转换
```

图片一侧：`gui-adaptive-250c4d4/12-tool-basic-info.png` 里 `0x0D` 有 **433** 个（134129 bytes，像素数据的一部分），`check-attr` 空输出、`hash-object --no-filters` 与 `--path` 同为 `21094281b11308c171eefc63f50c20fd8a7cfbca`（＝ `HEAD:…png` 的 blob）⇒ 没有任何规则碰它。

守卫第 7 条把这份依赖钉住（两份子目录 `.gitattributes` 的存在与 `* -text`），因为它是**唯一**阻止转换的机制：谁删掉它，`executed-service.mjs` 的 hash 就会从 `6ce91fd9` 变成 `7df7c72d`（上表第 2 组），7 份含 CR 的快照里只有它匹配根规则（`.log`/`.cjs` 不匹配，图片从不匹配）。

## 7. 未取得项与边界

### 7.1 git 历史里的 CRLF 无法追溯

本页只保证**当前 tree 零 CR ＋ 以后不再漂**。`#469` 那次提交、以及更早以 CRLF 入库的 blob 仍在历史里：`git log -p` 看旧版本依旧会看到 CR，`git blame` 也不会帮忙。要改写历史只能重写提交（`filter-branch`/`filter-repo`），那是另一个量级的风险，本片不做，也不建议做。

### 7.2 仍然含 CR 的字节（设计如此）

全仓 tracked 文件里，**改前 1625 个中 163 个含 CR 字节，改后 1628 个中 155 个**（本片新增 3 个文件，归零 8 个）。155 个里 148 个是 `docs/verification/assets/` 下的 png/jpg（二进制，CR 是像素数据的一部分），另外 7 个是证据快照文本：`i07-wechat-main8932ba5-pr80b5a6468/` 下的 `merged-tests.log`、`executed-bootstrap.cjs`、`executed-service.mjs`、`executed-ui.cjs`，以及 `local-knowledge-native-20261011/` 下的 `affected-tests.log`、`first-cycle.log`、`restart-smoke.log`。它们要么是二进制，要么被 `* -text whitespace=cr-at-eol` 钉成原样存取，**不属于**「文本行尾」问题。

复核命令与读数（2026-10-22 本分支 HEAD）：`git ls-files | Measure-Object` ⇒ **1628**；`git grep -l -P "\r" -- . | Measure-Object` ⇒ **155**；其中 `git grep -l -P "\r" -- "*.png" "*.jpg"` ⇒ **148**，余下 7 条正是上面点名的快照。与守卫的关键差异：这 155 个里**没有任何一个**落在 `SCAN_EXTS` 的扫描面内（`docs/verification/assets/` 已显式排除，§4.5/§4.6），所以「tracked 仍有 155 个含 CR」与「扫描面 CR=0」并不矛盾。

### 7.3 三处已过时的陈述（本片故意不改）

`#469` 之前「本仓库没有 `.gitattributes`」是真的，现在不真了。这句话在三个地方出现：`tools/verify-research-records.mjs:46-49`（哈希口径注释）、`docs/research/2026-10-18-research-records-gate.md:24`、`docs/research/legacy-allowlist.json` 的 `hashMethodNote`。

不改的理由：后两处是**已登记、已钉哈希的历史研究记录**（该工具自己的判据是「历史记录不得改写，只有登记与钉住这一条路」），单独改一处注释反而制造新的不一致；另开 PR 统一校正更干净。**口径本身未受影响**：LF 归一化 sha256 对 CRLF/LF 两种字节形态恒等，本片不动它一行代码。

### 7.4 没验的东西

Windows 上 `core.autocrlf=true` 的**第三方**检出（本仓库生效值是 `false`，见 §2.2）、GitHub 网页端在线编辑、`git add --renormalize .` 全仓重写、以及 CI（ubuntu）侧的行为——本页所有读数取自本机工作树、blob 与本仓库门禁，没有跨平台实测。
