# GY-I05 服务端档案与目录组件

2026-10-11；基线 main `d8588e0d666e2a8cba4f270800f73c79bd9d1542`。Refs #5，整项不关闭。

## 本次范围

新增 `/api/v1/me/profile` GET／PUT 和 `/api/v1/catalog/crops`、`/api/v1/catalog/regions` GET；小程序、定位、部署和其他写手分支不改。
路径／字段使用冻结 [OpenAPI](../../packages/contracts/openapi.json) 和 [状态协议](../architecture/state-contract.md)。
复用既有 `single_profiles`、`crops`、`regions`、`idempotency_keys`，无新增迁移。

空档案三个选择字段为 null、revision=1／ETag `"1"`；首次 PUT 写入 revision=2。
后续写入要求 Idempotency-Key 和当前强 If-Match，异键过期版本 409；同键／同体／原 If-Match 重试返回原回执，不重复递增。
相同键在不同主体间独立，回执含服务端归属和原档案结果，不含令牌、坐标或外部身份。
若随后有新修改，原幂等回执仍为原版本；消费者再次 GET 获取当前值，不把旧回执 ETag 当最新值。

请求守卫后事务再次按账号→会话顺序锁定，验证 active、auth_epoch、token_hash、会话未撤销且未到期；提交前再次查绝对到期。
每次重放也经过此验证；账号停用、epoch 变化、会话退出后不能返回旧成功。
私有响应均 no-store，所有者由服务端身份确定，输入禁止 owner/user/role 和原始坐标。
只更新单档案及它的幂等回执，不更新已保存记录或社区快照。

目录消费现有 [4 类作物](../../packages/knowledge/catalog/crops.json) 和 [浙江行政目录](../../packages/knowledge/catalog/regions-zhejiang.json) 作为批准范围，读取 PostgreSQL 对应 active／supported 行，并核对名称／父级／版本。
源记录缺少时不在生产数据库补假数据；未配置数据库明确 503。目录中的省级节点用于层级选择，不代表地区预警或有完整药剂资料。
本次没有重新确认 2023 行政码在现实中仍为最新；目录始终标明现有冻结版本，更新范围须另行审核。
目录稳定按 id／code 升序，默认20／最多50，签名游标绑定主体、目录类型、过滤、排序、当前批准目录水位，15分钟失效。目录变化或跨主体／过滤重用拒绝，不信客户端 owner。
