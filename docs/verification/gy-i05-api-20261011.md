## 本次范围

新增 `/api/v1/me/profile` GET／PUT 和 `/api/v1/catalog/crops`、`/api/v1/catalog/regions` GET；小程序、定位、部署和其他写手分支不改。
路径／字段使用冻结 [OpenAPI](../../packages/contracts/openapi.json) 和 [状态协议](../architecture/state-contract.md)。
复用既有 `single_profiles`、`crops`、`regions`、`idempotency_keys`，无新增迁移。

空档案三个选择字段为 null、revision=1／ETag `"1"`；首次 PUT 写入 revision=2。
后续写入要求 Idempotency-Key 和当前强 If-Match，异键过期版本 409；同键／同体／原 If-Match 重试返回原回执，不重复递增。
相同键在不同主体间独立，回执含服务端归属和原档案结果，不含令牌、坐标或外部身份。
若随后有新修改，原幂等回执仍为原版本；消费者再次 GET 获取当前值，不把旧回执 ETag 当最新值。

请求守卫后事务再次按账号→会话顺序锁定，验证 active、auth_epoch、token_hash、会话未撤销且未到期；提交前再次查绝对到期。
每次重放也经过此验证；账号停用、epoch 变化、会话退出后不能返回旧成功。
私有响应均 no-store，所有者由服务端身份确定，输入禁止 owner/user/role 和原始坐标。
只更新单档案及它的幂等回执，不更新已保存记录或社区快照。

目录消费现有 [4 类作物](../../packages/knowledge/catalog/crops.json) 和 [浙江行政目录](../../packages/knowledge/catalog/regions-zhejiang.json) 作为批准范围，读取 PostgreSQL 对应 active／supported 行，并核对名称／父级／版本。
源记录缺少时不在生产数据库补假数据；未配置数据库明确 503。目录中的省级节点用于层级选择，不代表地区预警或有完整药剂资料。
本次没有重新确认 2023 行政码在现实中仍为最新；目录始终标明现有冻结版本，更新范围须另行审核。
目录稳定按 id／code 升序，默认20／最多50，签名游标绑定主体、目录类型、过滤、排序、当前批准目录水位，15分钟失效。目录变化或跨主体／过滤重用拒绝，不信客户端 owner。

## 修订1：限权运行角色

监工 [review 5480214416](https://github.com/GengYunChuChao/GengYun/pull/74#pullrequestreview-5480214416) 对旧HEAD `dace67d2d5a0dd99ef54d28a2e93f85a2665c1fc` 指出：旧49项夹具由owner查询，掩盖运行角色权限缺失。该旧结果保留为历史，不证明可由运行角色执行。
本轮正常同步 main `427ddb448b7e315719de8e03ba6ca048fa2e8246`，保留已合登录／生命周期保护；不改它的实现。

新增 [profile_runtime.sql](../../services/api/db/roles/profile_runtime.sql)，独立 `gengyun_profile_runtime` NOLOGIN、非超级用户、无建库／建角色／复制／绕RLS权限。
不改旧角色、不增加迁移或全表ALL授权。与原样 `gengyun_auth_privacy` 组合，后者继续负责身份、会话及幂等表。

| 表 | 本组件新增列权限 | 行锁及边界 |
| --- | --- | --- |
| crops | SELECT id/name/active；UPDATE name | FOR SHARE需要至少一个列的UPDATE；不授权active／id修改、INSERT、DELETE |
| regions | SELECT code/name/parent_code/catalog_version/supported；UPDATE name | FOR SHARE同理；不授权支持标志、代码、父级、版本修改、INSERT、DELETE |
| single_profiles | SELECT user_id/crop_id/region_code/region_catalog_version/revision；INSERT相同5列；UPDATE作物／地区／目录版本／revision／updated_at | FOR UPDATE及首次写入／替换；不授权user_id修改或DELETE |
| users/sessions/idempotency_keys | 新角色不新增权限，复用auth_privacy既有列权限 | 账号updated_at的UPDATE支持锁；state/auth_epoch仍不可改 |

PostgreSQL行锁要求UPDATE列权限，故目录name列确有SQL UPDATE权限，不能宣称完全只读；当前API没有目录改名入口。
这是受信服务账号组，不能给终端用户直接SQL登录；账号行锁和对象归属仍由服务实现，不宣称每用户RLS。
若不接受该列锁权限，应先另行审核目录并发一致性策略，而非静默使用owner。

引导由专用迁移／运维账号执行，API LOGIN不拥有表。先按现有交接完成全部迁移和auth_privacy角色；运行本新增角色脚本，再将两组授予单独的受限LOGIN：

```sql
-- 仅示例账号名；实际LOGIN由运维私密通道创建，无密码写入脚本。
GRANT gengyun_auth_privacy, gengyun_profile_runtime TO gengyun_api_login;
```

现有本地工具不会自动安装新角色，操作人需显式执行新增脚本并给现有受限本地LOGIN授予该组；不要用迁移owner作为API连接的替代。
首次脚本在角色已存在时拒绝，不删除／覆盖既有角色。只授权现有指定列，无未来对象默认权限。
角色回撤前停止相应消费者，由运维REVOKE组成员关系及本脚本列授权后再按依赖移除组；这不是结构迁移，也不删除档案数据。
