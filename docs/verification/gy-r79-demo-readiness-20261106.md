# R79 演示就绪矩阵（2026-11-06）

本页记录 2026-11-15 演示前的**本机实测**结论：哪条通道能演、哪些前置已具备、哪些还缺、哪些环节**不能**演以及为什么。
它不替代 `docs/requirements.md` 的验收口径，也不是准确率或性能评估（见第 7 节边界）。

## 0 范围与口径

- 实测环境：单台 Windows 开发机 + 本地 PostgreSQL 17.11 + 微信开发者工具（真机调试），API 以 `real` 模式运行，数据落在**演示库**（本地实例，非生产）。
- 实测时间窗：2026-11-05 15:00Z–18:00Z。
- 凭据来自项目私密区，**不进仓库、不进日志**；本页所有读数均不含密钥、AppSecret、连接串或用户标识。
- 按 `docs/pr-review-policy.md` 第 11 节（证据豁免）仍守的两条底线：外部世界事实不写成「已验证」；不回填旧读数。因此下文的「实测」只指**本机这一条链路跑通**，不等于生产可用或平台审核通过。

## 1 通道判定

| 通道 | 结论 | 依据 |
| --- | --- | --- |
| 真机调试（开发版） | **可用**，演示走这条 | 勾选「不校验合法域名」后可访问 `http://<私网 IP>:<端口>`；实测手机请求服务端日志出现 200，含 `/public/home`、`/auth/wechat`、`/me/consents` |
| 预览版 / 体验版 | **不可用** | 两者对请求域名做硬校验，只允许已备案域名的 https；把 `urlCheck` 关掉也不生效，扫码后报网络请求失败 |
| `stub` / `preset_demo` 执行模式 | 仅兜底 | 这两个模式下首页数据面按设计不可用；媒体与审核域永不接真实端口。要内容就得发布数据（本轮裁定为不发布） |

演示的前置结论：**走真机调试 + `real` 模式 + 演示库**。每次重编译会断开调试连接，需重新扫码。

## 2 前置条件

| 项 | 状态 | 读数 |

| 微信 AppID / AppSecret | ✅ | `jscode2session` 对无效 code 返回 `40029`（凭据被接受、无 IP 白名单阻断）；真机 `/auth/wechat` 200 |

| 演示库数据 | ✅ | 82 张表；同意政策两用途各一行；三张种子表共 22 行受体与政策绑定；功能开关按演示需要显式设置 |

| 演示自检 | ✅ | 只读自检 13 项全 PASS（含「演示副本补丁仍在」与「授权落在当前 epoch 且带接收方」） |

## 3 已实测的端到端链路

1. 真机登录 → `/auth/wechat` 200 → 首页、社区、消息、我的等只读页均 200。
2. 授权（两用途）→ 上传（201）→ 对象存储 PUT（2xx）→ `complete`（202，state=ready）→ `POST /recognitions`（202）→ 任务终态 `succeeded` 或 `uncertain`。
3. 识别全链路在 `real` 模式下经**协议翻译层**把冻结协议 `gy-recognition-live-v1` 转成厂商 OpenAI 兼容请求；候选结果写回任务记录，客户端按物种 id 解析中文名与关联资料。
4. 撤回 `media_processing` → 后续上传 403；在途任务被终止（错误码语义见第 5 节缺口）。

## 4 可演与不可演

| 环节 | 是否进演示 | 说明 |
| --- | --- | --- |
| 登录、首页空态、知识库空态、参考页（离线）、社区只读、消息、我的/收藏/历史 | ✅ | 首页与知识库按未核对数据的真实状态呈现空态，**不伪造人工复核记录** |
| 拍照识别（相册选图） | ✅ | 只能选目录内 8 类；稗草/藜表现好，禾本科互串需如实说明「属级近似」 |
| 授权页与撤回 | ✅ | 但**不要在授权页重新点授予**：每点一次进入新 epoch，预置的接收方绑定会落回旧 epoch（见第 5 节） |
| 发帖/评论 | ❌ | 审核域未接真实端口，按 fail-closed 返回 503 |
| 语音识别/合成、标签 OCR | ❌ | 服务端接口已实测 2xx，但客户端从未演练；**服务端通了不等于能演** |
| 上传体验版 / 正式发布 | ❌ | 需已备案域名的 https，非本机可解 |

## 5 已知缺口（逐条对应 issue）

- **实时识别缺少服务端协议接收面**（`Refs #1003`）：客户端侧已有外发真实适配器与冻结协议，缺的是服务端按该协议接收并转发的实现；本机演示用一层等价翻译层顶替，该层不在仓库内。
- **授予 `media_processing` 时客户端传空 `recipient_ids`**（`Refs #1004`）：服务端在出网预留时才 403，用户按正常交互授权后识别必然失败。客户端侧已改为让用户显式选择接收方并随 `#1005` 合入 main；服务端仍建议补一道非空校验（`Refs #1006`）。
- **撤回导致在途任务终止时错误码语义不准**（未单独开单，并入 `#1004` 语境）：撤回竞态下单次任务以 `PROVIDER_OUTCOME_UNKNOWN` 结束，建议单列「授权撤回取消」语义。

## 6 复现方式（不含任何密钥）

演示服务由本地脚本拉起：数据库 → 演示库 → API（监听 0.0.0.0，`real` 模式，带媒体域装配批准参数）→ 协议翻译层；随后用只读自检脚本按 13 项核对，其中包含端口、健康检查、首页、局域网地址、小程序副本指向、防火墙规则、当前 epoch 授权、功能开关、最近任务、外网可达性、演示副本补丁存在性等。
这些脚本位于会话级工作目录，**未提交仓库**；本节只描述步骤，不依赖具体脚本路径。

## 7 未验证与边界

- **没有准确率评估**：第 2.1 节的识别读数是三张公开样本的观察，不构成准确率证据；`docs/architecture/ai-ops-spec-status.md` 中「零真实调用、零准确率证据」的结论对本基线仍然成立（本轮真实调用发生在本地翻译层环境，不是已审供应商）。
- 只在一台安卓真机、一条 Wi-Fi 上验证过；换网络需重跑拉起脚本并重新扫码。
- 未验证并发、多用户、弱网与断网恢复。
- 未验证生产数据库、生产对象存储桶与正式域名。
