## 1 目的与边界

**要证的是这条供应商链路通不通**，三段一连：

1. 真实 `TextToVoice` 合成出音频（请求 `Codec=wav`，返回 `wav`）；
2. 该音频**原样**通过仓内 `requireLiveAsrWav()` 的产品输入剖面校验（ACCEPT，未裁剪未转码）；
3. 同一份音频真实送 `SentenceRecognition`，拿回 `Result` 与 `AudioDuration`。

**⛔ 本页不证什么（必须与上面的结论一起引用，不得单取结论）**：

- **不构成准确率样本**：**N=1**，且这 1 条是**合成语音**，不是真人录音。因此本页**不产生**
  任何 ASR 准确率、识别质量、可懂度或召回结论；**真实样本数仍为 0**
  （口径同 `docs/evaluation/sample-gap-register.md`，该清单里 ASR 能力域的真实样本到位数为 0）。
- **不证**真实用户环境、真实设备播放、供应商账单、逐词时间戳（逐项见 §7）。
- 环回**不保证字节级可逆**：供应商会对合成文本做书写规范化，见 §5。

## 3 本地校验（`requireLiveAsrWav()`）

```
verdict:     ACCEPT
bytes:       140204
durationMs:  4380
理由:        16k / 单声道 / 16bit PCM 的 WAV 头与 chunk 遍历均通过，
             base64 后未超 3145728 字节，时长未超 60 s
```

- **未裁剪、未转码**：TTS 直出的 WAV **原样**满足产品 ASR 路径的本地输入剖面。
- 这一步判的是「能不能把这段合成音频喂进产品路径」，**不是对供应商的调用**；
  它先于 ASR 的预留与发送执行（`requireLiveAsrWav()` 的 `ACCEPT` 是 ASR 那一发的前置条件）。

## 5 逐字对账（如实写，不加修饰）

| 项 | TTS 输入 | ASR 输出 |
| --- | --- | --- |
| 文本 | `玉米除草剂每亩用量三十毫升，注意安全间隔期` | `玉米除草剂每亩用量30ml，注意安全间隔期。` |
| 码点数 | 21 | 22 |
| 标点 | `，`（1 个） | `，` `。`（2 个） |

**判定：`有增删`**（按「逐字相同 / 仅标点差异 / 有增删」三分类的口径）。
差异**仅两处**，位置逐条如下（码点下标从 0 起）：

| 位置 | 差异 | 归属 |
| --- | --- | --- |
| 9–12 | `三十毫升` → `30ml` | 4 字被替换（**非随机丢字**：`三十` → `30`，`毫升` → `ml`） |
| 21 | 末尾多出 `。` | 句末标点新增 |

其余 **17 个码点**（`玉米除草剂每亩用量` ＋ `，注意安全间隔期`）**逐字相同**，顺序与字形均未变。

**这处差异不是「听错」，是供应商的规范化**：`三十毫升` 与 `30ml` 是同一数量的两种书写，
供应商做了**中文数字→阿拉伯数字 ＋ 单位缩写**的规范化。由此得到两条必须遵守的口径：

1. **⛔ 不得把「ASR 文本 == TTS 输入」当环回验收判据**——这一句就会**假失败**，而链路其实是通的。
2. 可用的判据是：**归一化后**（去标点 ＋ 数字/单位归一）逐码点比对，或直接比对关键实体。
   本次三处关键实体（`玉米除草剂`、`每亩用量`、`注意安全间隔期`）**全部命中**。
