## 2 契约事实（读 `packages/contracts/openapi.json` 原文，非凭记忆）

契约里 OCR 域**恰好 5 个** operationId（与阶段 1 一致）：

| 方法 路径 | operationId | 请求 | 成功响应 | 必填头 |
| --- | --- | --- | --- | --- |
| `POST /ocr` | `createOCR` | `MediaJobInput` | `202 JobEnvelope` | `Idempotency-Key` |
| `GET /ocr/{id}` | `getOCR` | — | `200 OCREnvelope` | — |
| `DELETE /ocr/{id}` | `deleteOCR` | — | `202 AckEnvelope` | `Idempotency-Key` + `If-Match`（`x-version-required: true`） |
| `PATCH /ocr/{id}/correction` | `correctOCR` | `OCRCorrectionInput` | `200 OCREnvelope` | `Idempotency-Key` + `If-Match` |
| `POST /ocr/{id}/verify` | `verifyOCR` | `VerifyInput` | `200 VerificationEnvelope` | `Idempotency-Key` + `If-Match` |

- `IfMatch` 契约描述：**「目标当前强ETag，不允许`*`；缺失428，不匹配409」**，`pattern: ^"[1-9][0-9]*"$`
- `IdempotencyKey`：`minLength 8 / maxLength 128`，**「同主体/方法/路径键域，hash包含If-Match；重放前重新鉴权」**
- `Ack = { accepted: boolean }`，`additionalProperties: false`
- `Meta = { request_id(uuid), contract_version(const "1.0.0"), execution_mode }`，`additionalProperties: false`
- `JobState` 七值；`OCRResult = { kind: const "ocr", value: OCR }`

## 3 状态码 / 错误码映射（本片实测）

| 情形 | HTTP | `error.code` |
| --- | --- | --- |
| 受理成功 | 202 | — （`data` 为 `Job`） |
| 读取/校正/核对成功 | 200 | — |
| 删除成功 | 202 | — （`data = {accepted:true}`） |
| 缺/过短 `Idempotency-Key` | 400 | `IDEMPOTENCY_KEY_REQUIRED` |
| `If-Match` 缺失 | **428** | `REVISION_REQUIRED` |
| `If-Match` 格式非法（含 `*`、`abc`） | 400 | `INVALID_REQUEST` |
| `If-Match` 与当前 revision 不匹配 | **409** | `REVISION_CONFLICT` |
| 同键同体**并发**落败 | 409 | `REQUEST_IN_PROGRESS` |
| 同键异体 | 409 | `IDEMPOTENCY_CONFLICT` |
| body 多余字段 / 非法 `media_id` / `media_revision<1` | 400 | `INVALID_REQUEST` |
| 路径 `id` 非 uuid | 400 | `INVALID_REQUEST`（Fastify `format: uuid` 生效，实测） |
| 他人记录 / 不存在（GET/PATCH/DELETE） | 404 | `NOT_FOUND`（**两者错误体逐字段同形**） |
| 无会话 | 401 | `SESSION_REQUIRED` |
| real 型提供者缺凭据 | **503** | `PROVIDER_UNAVAILABLE` |

## 4 实现说明（沿用既有管道，不另造）

- 路由插件签名 `registerOcrRoutes(app, config, guards, service)`；沿用 `guards.requireUser` 作为
  `preHandler`、`readIdentity(request).userId` 取归属者、`routes/support.ts` 的 `buildMeta`、
  `app.ts` 的 `setErrorHandler` / `setNotFoundHandler` 产生契约封套；私有响应一律
  `Cache-Control: no-store` + 资源 revision 强 `ETag`。
- `Idempotency-Key` / `If-Match` **不放进 Fastify schema**：这两个头的契约错误码
  （`IDEMPOTENCY_KEY_REQUIRED` / `REVISION_REQUIRED` / `INVALID_REQUEST` / `REVISION_CONFLICT`）
  由服务层统一判定，与 `routes/profile.ts`、`routes/consents.ts` 的既有做法一致；
  若交给 schema，会把"键太短"改写成通用校验错误，与契约码不符。
- body/params 的 schema **逐字段照抄契约**（`additionalProperties:false`、`anyOf[...,null]`、
  `maxItems 20`、`pattern ^33[0-9]{4}$`、`format: uuid`），与 `app.ts` 的
  `ajv.customOptions.removeAdditional = false` 配合，多余字段会被显式拒绝而不是被静默剔除。
- **为写契约要求的 `ETag` 而做的薄适配**：`verifyOCR` / `deleteOCR` 的响应声明了强 `ETag`，
  但 `OcrVerification` 是契约 `additionalProperties:false` 的五字段对象（**不能**塞 revision），
  而 `deleteOcr` 原本只回 `{accepted:true}`。故**新增** `verifyOcrWithRevision` /
  `deleteOcrWithRevision`（同一实现、额外带回记录 revision），既有
  `verifyOcr` / `deleteOcr` 改为**委托**、返回值与语义**逐字节不变**。
  替代方案（路由在 verify 之后再读一次记录）会多一次 I/O 且有 TOCTOU，故不采用。
  证据：`node --test "tests/unit/ocr*.test.mjs"` 在该改动**前后均为 119/119**。
- 删除响应只下发 `{ accepted }`；内部 revision 只进 `ETag`，不进响应体（否则违反 `Ack`
  的 `additionalProperties: false`）。
