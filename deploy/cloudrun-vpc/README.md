| **微信云托管** | `cloud.weixin.qq.com/cloudrun` | 依附微信小程序/公众号，**一对一绑定一个腾讯云账号** | `wx.cloud.callContainer` 可直接取 openid |

## 3 逐一判定项

每项固定四段：**要查什么 → 在哪查 → 可能取值 → 如何判读**。完整命令见 [verify-vpc-linkage.md](verify-vpc-linkage.md)。

### 判定项 ① 账号归属：环境绑定的腾讯云账号 UIN 是否等于 `vpc-h33f1h5a` 所属账号

- **要查什么**：`prod-d1g6qe87c4f2d7061` 所依附的微信小程序/公众号**一对一绑定的腾讯云账号 UIN**；与创建 `gengyun-vpc`（`vpc-h33f1h5a`）时使用的腾讯云账号 UIN 是否**同一个**。
- **在哪查**：
  - 微信云托管控制台 →「设置 → 环境设置 → 基础信息 / 充值与账单」；官方原文：点击「充值与账单」，进入**当前云托管账号背后绑定的腾讯云账号**的费用中心（[环境设置](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/guide/env/envsetting.html)）。
  - 腾讯云控制台 →[账号信息](https://console.cloud.tencent.com/developer)（用创建 VPC 的那个账号登录后查看 UIN）。
  - 命令行（有凭据时）：`tccli sts GetCallerIdentity` 打印当前凭据所属账号。
  - 绑定/解绑状态：腾讯云控制台「账号信息」页的「微信公众平台」登录方式旁可【解绑】（[账号说明](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/guide/account/)）。
- **可能取值**：同一账号；不同账号；无法确定（无入口权限/未登录正确账号）。
- **如何判读**：
  - **相同** ⇒ 下拉框为空的原因不是账号错配，转查 ②③④。
  - **不同** ⇒ 高概率即"无选项"的根因（见 4.1）。**注意破坏性**：官方明确"更换绑定的腾讯云账号，**必须销毁当前所有环境且无法恢复**"；此项**严禁自行执行**，只能由用户决策。
  - 官方还明确两条硬约束：**一个腾讯云账号只能绑定一个小程序/公众号**（"不支持多个小程序/公众号/第三方服务商/小游戏/小商店绑定同一个腾讯云账号"）；若该小程序此前开通过云开发并绑定过腾讯云账号，云托管会**自动沿用且不支持更换**。
- **记录方式**：UIN 等真实账号标识**只写入仓库外的私密目录**（如 `E:\GengYunPrivate`），**不得**写入本仓库任何文件。

### 判定项 ② 地域：环境地域与 VPC 地域是否一致（上海 `ap-shanghai`）

- **要查什么**：环境所在地域；`gengyun-vpc` 及其子网所在地域；两者是否都是上海。
- **在哪查**：
  - 微信云托管 →「环境设置 → 基础信息」显示"**环境部署地域**"（同上文档）。
  - 服务公开域名也可旁证地域：官方 CLI 返回样例 `DefaultPublicDomain` 形如 `https://server.ap-shanghai.run.tcloudbase.com`（[CLI 工具](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/guide/cli/)）。
  - 腾讯云 →[VPC 控制台](https://console.cloud.tencent.com/vpc)（先把左上角地域切到**上海**，确认能否看到 `gengyun-vpc`）；命令行 `tccli vpc DescribeVpcs --region ap-shanghai`。
- **可能取值**：上海—上海；云托管上海而 VPC 非上海；地域取值为 `ap-shanghai` 之外（如 `ap-guangzhou`）。
- **如何判读**：
  - 【已确证·文档】文档两处写明云托管底层资源在**上海**且不支持跨地域："微信云托管底层资源地域部署在上海"；"目前云托管资源地域暂只支持**上海**，所以业务在创建腾讯云资源时也请选择上海地域，**暂不支持跨地域资源互联**；例：支持上海 - 上海，不支持上海 - 其他地域"（环境创建页、环境设置页）。
  - **同为上海** ⇒ 排除地域因素。**VPC 不在上海** ⇒ 该 VPC 不会出现在下拉框中（见 4.2）；修法只能是"在上海地域另有可用 VPC"，但**新建资源属用户决策**。
  - 腾讯云地域取值表中，上海为 `ap-shanghai`（[私有网络 公共参数 · 地域列表](https://cloud.tencent.com/document/api/215/15758)）。

  - 旧版：微信云托管 →「设置 → 环境设置 → **资源互联**」（查看授权状态）。
  - 自查指南：官方[资源互联调用腾讯云资源自查指南](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/scene/noun/vpc.html) 第 2 步即"前往「微信云托管控制台 - 设置 - 环境设置 - 资源互联」中查看授权状态"。
- **可能取值**：新版入口可选 VPC/子网；旧版入口显示未授权/无资源包；两处都不可用；入口不存在（权限或产品形态不符）。
- **如何判读**（以下均为文档原文要点）：
  - 【已确证·文档·新版机制】"服务已升级对接腾讯云私有网络 VPC 能力。**当前已不再依赖资源互联能力**，可以通过在服务上配置私有网络 VPC，即可实现服务到私有网络 VPC 的通信。""在服务配置上启用私有网络 VPC 后，选择需要对接的私有网络 VPC 及子网，并保存配置。**保存后服务将会发布新版本**。"（[服务设置](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/guide/service/pipeline.html) §7）
  - 【已确证·文档·不依赖购买】"资源互联能力已经升级为服务上的私有网络配置能力。**当前无需购买服务资源包或互联资源包，也可以直接使用服务对接腾讯云私有网络 VPC 能力。**"（[环境设置](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/guide/env/envsetting.html)）
  - ⇒ 该段与同页旧段（"需业务购买互联资源包"）**并存且矛盾**：处置规则见第 5 节第 4 条——**以控制台实际提示为准**，并把两处入口的提示原文抄录留证；在拿到原文前不替用户取舍。
  - 【已确证·文档·版本差异】"**2022 年 7 月后创建的环境，由于架构升级不再显示 VPC 信息**"（环境创建和管理）。⇒ 老环境与新环境的可见入口不同，这本身可能造成"看不到选项"的观感差异。
  - 【已确证·文档·旧版配额（适用于"资源互联"旧能力）】"1 个云托管账号目前暂时只支持 **1 个环境**使用资源互联能力"；"资源互联只支持授权 **1 个 VPC**，暂不支持多个"；"资源互联带宽峰值最大为 5 Gbps"；"资源互联具有**环境属性**"。⇒ 若别的环境已占用旧能力，当前环境可能无法再授权。
  - 【待确证】新版「服务维度 VPC」是否仍受上述"1 环境/1 VPC"限制：**未找到**明确说明，需以控制台实际提示为准。
  - 【推断·重要副作用】启用私有网络会**消耗所选子网的空闲 IP**（每实例通过 VPC 弹性网卡取 IP）："请确保 vpc 的子网中有足够的空闲 IP 可供分配或使用。**IP 不足的情况下，会导致实例无法正常启动**，会导致云托管服务无法创建、更新或扩容等问题。"⇒ 子网可用 IP 数与弹性网卡配额必须先核。
  - 【推断】`10.20.0.0/16` 属常用私网段，官方建议"将腾讯云网络 VPC CIDR 配置为非常用的地址范围"，保存时若提示 `vpc cidr conflict` 需调整 CIDR。本网段是否冲突：待确证。

### 判定项 ④ 授权/CAM：谁有读权限、云托管服务角色是否已授权

- **要查什么**：当前操作者角色；只读核验者是否具备 `DescribeVpcs`/`DescribeSubnets`/`DescribeSecurityGroups` 等读权限；云托管侧是否存在需授权的服务角色。
- **在哪查**：
  - 微信云托管 →「设置 → **权限设置**」`https://cloud.weixin.qq.com/cloudrun/settings/privilege`（[权限设置](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/guide/authset/)）。
  - 腾讯云 →[CAM 控制台](https://console.cloud.tencent.com/cam)（策略与子账号）。
  - 命令行判读：`tccli vpc DescribeVpcs --region ap-shanghai`。
- **可能取值**：`TotalCount>0` 且含 `vpc-h33f1h5a`；`TotalCount=0`；`AuthFailure.UnauthorizedOperation`（无权限）；其他错误。
- **如何判读**：
  - 【已确证·文档】微信云托管自带角色体系：**云托管管理员 / 环境管理员 / 开发者**，权限按环境细分；授权入口即上面的权限设置页。⇒ **当前操作者的角色本身就是判定项**，不是所有成员都能改网络配置。
  - 【已确证·本机】同类只读调用在缺权限时返回 `AuthFailure.UnauthorizedOperation`（本仓库既有实测记录：[资源交接](../../docs/verification/resource-handoff.md)："TTS两项只读查询均被AuthFailure.UnauthorizedOperation拒绝"）。⇒ 该错误码可直接判读为"凭据可用但动作未授权"。
  - 【待确证】**云托管服务角色**：微信云托管的权限清单里**没有** VPC/资源互联条目（权限清单末项为"环境设置：环境设置查看 / 充值与账单 / 切换成微服务框架"），腾讯云侧亦未查到"云托管服务角色"的官方名称与授权步骤。
  - 【未找到依据】微信云托管/腾讯云开发文档中未找到"必须先授权某个云托管服务角色才能绑定 VPC"的原文。**因此不得凭猜测创建或授权任何服务角色/CAM 策略**；若控制台出现授权提示，由用户按提示原文判断并记录。

### 判定项 ⑤ 环境类型/版本限制：是否支持绑定 VPC、是否要求特定套餐

- **要查什么**：当前环境是否属于支持服务维度 VPC 的形态；是否要求套餐/资源包；是否已冻结。
- **在哪查**：微信云托管「环境设置 → 基础信息」（付费方式/环境 ID）、「服务设置 → 私有网络设置」、服务列表状态、资源监控用量。
- **可能取值**：可按量计费且有私有网络入口；无入口；环境已冻结。
- **如何判读**：
  - 【已确证·文档】新版机制**不要求**购买资源包即可"服务对接腾讯云私有网络 VPC"（环境设置页原文，见 ③）。⇒ "必须买套餐才能绑 VPC"目前**无依据**。
  - 【已确证·文档】环境配额："一个「小程序/公众号」账号最多支持创建 **3 个**微信云托管环境，仅第 1 个环境带有 3 个月免费额度"；"不同环境独立计费"，"**不同环境无法共享资源包**"（环境创建和管理）。
  - 【已确证·文档】冻结风险："如微信云托管环境在 **30 天内未产生任何请求调用**，则该环境将会被冻结"；冻结超 180 天自动销毁（环境创建和管理）。⇒ 长期不部署的环境可能被冻结，核验时须先确认环境状态。
  - 【待确证】该环境是否曾走"系统创建 VPC + 微小型 NAT 网关"（创建环境时若未选自有上海 VPC，后台自动创建）：**该自动创建的 VPC 是否出现在下拉框备选中，文档未说明**。

### 4.11 实测带出的结构性风险：跨账号很可能"连不通"（需用户决策）

若 1.1 的那一步比对确认**环境绑定账号 ≠ `gengyun-vpc` 所属账号**，则要正视一个结构性问题：

- 云托管服务在选择私有网络时，下拉候选**只来自云托管环境背后绑定的那个腾讯云账号**（官方原文见 4.1）。⇒ 把 PostgreSQL 建在**本凭据账号**的上海 VPC 里，**很可能无法被云托管服务选中**，因此这条计划在结构上就不成立，而不是"再调一个参数"能解决。
- 现有约束的冲突：用户明确"**不要重建既有网络**"，而 `gengyun-vpc` 在本凭据账号内且是唯一 VPC（实测）⇒ **不应删除或重建它**。
- 可选路径（**全部属用户决策，本单不执行任何一项**）：
  1. **在绑定账号侧建设**：用绑定账号登录，在其上海地域准备 VPC/子网（该账号目前是否有 VPC 待查）并创建 CVM/PostgreSQL，云托管服务选择该 VPC。代价：需该账号的登录与付费，且原 `gengyun-vpc` 闲置。
  2. **把云托管环境换绑到本凭据账号**：官方明确"更换绑定的腾讯云账号，**必须销毁当前所有环境且无法恢复**" ⇒ **破坏性**，会毁掉现有 `prod` 环境，与"不要重建"的意图直接冲突，**极不推荐在核验阶段考虑**。
  3. **跨账号网络方案（云联网/跨账号对等连接等）**：官方微信云托管文档中**未找到**支持"云托管环境连接到非绑定账号 VPC"的依据 ⇒ 记【未找到依据】，**不得**据此指导建设。
- **本单结论**：在完成 1.1 那一步比对之前，**不要**创建 CVM、不要购买资源包、不要动 VPC；一旦确认账号错配，请先做路径选择决策，再谈连接验证。

**不构成原因、但常被误当成原因的说法**：

- 【未找到依据】"购买 36 元资源包就能让下拉框出现选项"。见第 5 节。
- 【未找到依据】"必须先在腾讯云侧创建/授权某个云托管服务角色，下拉框才有数据"。
- 【不成立】"把既有 VPC 删掉重建就行"——用户明确不重建既有网络，且删 VPC 不影响账号归属错配。

## 5 关于"购买 36 元资源包是否一定解决"的官方依据核查

**结论：【未找到依据】支持"购买 36 元资源包一定能解决下拉框无选项"；而且官方文档存在与新机制相反的明确表述。**

已查到的原文（同一份[环境设置](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/guide/env/envsetting.html)页面内**新旧两段并存**）：

- 新机制段落（原文）："资源互联能力已经升级为服务上的私有网络配置能力。**当前无需购买服务资源包或互联资源包，也可以直接使用服务对接腾讯云私有网络 VPC 能力。**更多详情可以参考服务设置中的私有网络设置说明。"
- 旧机制段落（原文，同一页）："云托管支持同地域通过授权 VPC 在内网打通腾讯云资源……需业务**购买互联资源包**以获取腾讯云资源互联能力；该互联资源包包含容器计算资源、腾讯云资源互联能力等……**互联资源包购买一次即可永久获取腾讯云资源互联能力**。"
- 同页「服务资源包」事实（原文）：原"互联资源包"已改名"服务资源包"；**售价 36 元**（原价 53.84 元，6.68 折）；有效期 **3 个月**；**环境级购买，不可转移**；**一次性购买不可续费、不支持退款**；"资源包为不定期优惠，具体规格和价格以控制台购买页面为准"。
- 【已确证·文档】[服务设置](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/guide/service/pipeline.html) §7 再次确认新路径："服务已升级对接腾讯云私有网络 VPC 能力。**当前已不再依赖资源互联能力**。"

据此可确定的判读：

1. "36 元"对应的官方商品是**服务资源包（原互联资源包）**，环境级、3 个月、不退款——**它不是排障手段**，不能先买来"试试看"。
2. 官方**新段明确"无需购买"即可使用服务对接 VPC**，因此"必须买才出现下拉选项"与文档不符；在同一页仍保留旧段"需业务购买互联资源包"，属**文档自相矛盾**，不能只取其一当结论。
3. 无论取新段还是旧段，**都不能解释账号归属错配或地域不符**——这两个最可能的原因与购买无关。⇒ 先做判定项 ①②，再谈是否涉及付费。
4. **矛盾处置规则（可执行）**：官方同页新旧表述并存时，**以控制台实际提示为准**。请把两处入口的**页面提示原文照抄**——「服务设置 → 私有网络设置」与「设置 → 环境设置 → 资源互联」各自的提示文案、按钮文字、按钮是否可点击——粘贴到 [user-console-actions.md](user-console-actions.md) 的 C2/C3/C5 指定空白处。**在拿到原文之前，不得替用户选定"必须购买"或"无需购买"任何一边，也不得据此下结论**；原文与本文档冲突时以原文为准，并把差异记录在案。
5. **购买/付费属用户独占决策，本单不执行、不代购、不代付款。**
